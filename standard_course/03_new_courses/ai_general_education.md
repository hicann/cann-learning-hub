## 二、设计理念与问题主线

### 2.1 问题主线（三问递进）

三讲由一条递进的核心问题链贯穿——**从 AI 的来龙去脉出发，走进大模型内部，最终落到算力底座**：

```
第 1 讲「AI 是怎么一步步走到今天的？」  → 人工智能的来龙去脉与演进到大模型（历史之问）
第 2 讲「大模型到底在算什么？」        → 大模型是什么、在算什么（本质之问）
第 3 讲「大模型的算力谁来支撑？」      → NPU 与 CANN 如何支撑人工智能算力（支撑之问）
```

> 问题闭环：故事从算法史开始（第 1 讲），在模型里到达高潮（第 2 讲），最终由软硬协同收束（第 3 讲）——回到软件（CANN）完成叙事闭环。

### 2.2 业界最佳实践落地

| 实践来源 | 本课程落地方式 |
|---------|--------------|
| 问题式学习（PBL） | 每讲以一个**核心问题**命名并贯穿；知识为回答问题而出现，不做知识罗列 |
| 认知冲突开场（discrepant event） | 每讲前 5 分钟用竞猜 / 游戏制造"原来如此"时刻（如：猜下一个字、笔记本训练 GPT-3 要多久） |
| 叙事化历史（Sandel / CS50 风格） | 第 1 讲把七十年 AI 史讲成一部"三起两落"的剧情片：每个转折都由一个具体困境触发 |
| 直觉优先（Ng / Li 风格导论课） | 类比优先、去公式化：全课唯一"公式"是 `y = f(x)`；神经元=大脑比喻、训练=学骑车、CANN=翻译官+管家 |
| 互动工具箱（CS50 式课堂） | 数量级竞猜、举手投票、白板共创、Think-Pair-Share、一分钟纸 / 门票卡，每讲 ≥ 2 次互动 |
| 每讲一个带走物（takeaway） | 每讲结尾"一句话带走"+ 下讲悬念；第 3 讲以一分钟纸回收全部问题链 |
| 螺旋式课程（Bruner） | 概念反复回访：第 1 讲埋下的"函数"在第 2 讲变大（概率计算器）、在第 3 讲被算力约束 |

## 五、分讲详案

### 第 1 讲｜人工智能的来龙去脉：到底什么是 AI，如何演进到大模型？（45'）

| 时段 | 环节 | 要点 | 互动设计 |
|------|------|------|---------|
| 0–5' | 开场竞猜「哪个是 AI？」 | 四个场景：抖音推荐 / 人脸解锁 / ChatGPT / 计算器——哪个是 AI？→ 全都是；但计算器引出关键分野：**规则写死的程序 vs 从数据里学出来的程序** | 🗳️ 举手投票 |
| 5–17' | 问题一：到底什么是人工智能？ | 1950 图灵之问「机器能思考吗」与图灵测试；AI ⊃ 机器学习 ⊃ 深度学习三层同心圆；规则驱动 vs 数据驱动对照（手写数字识别：人写规则必然失败 → 机器看十万张例子学会）；**模型 = 函数 `y = f(x)`**（全课唯一公式），训练 = 不断调参数（学骑车比喻） | 苏格拉底追问链 |
| 17–31' | 问题二：AI 是如何一步步演进的？ | 三次浪潮与两次寒冬时间轴：① 符号主义（1950s–80s，人写规则，专家系统撞墙入冬）；② 统计机器学习（1990s–2010s，从数据学统计规律）；③ 深度学习（2012 ImageNet 时刻翻盘）——神经元 / 神经网络（模仿大脑的函数叠罗汉）、"深度" = 层数多；成功三要素：**数据（教材）× 算法（教法）× 算力（教室）** | 时间轴走读：每个转折先给困境再给突破 |
| 31–42' | 问题三：如何演进到大模型？ | 深度学习的瓶颈：一个任务一套标注数据，学一个会一个；**预训练革命**：让模型自己"读书"——2017 Transformer（注意力 = 自动划重点，只讲直觉）→ 2018 GPT → 2020 GPT-3（1750 亿参数，数量级竞猜：vs 人脑约百万亿突触连接）→ 2022 ChatGPT 出圈；Scaling Law 一句话：规模越大能力越强 | 🗳️ 数量级竞猜 |
| 42–45' | 收束 + 悬念 | 一句话带走：「七十年 AI 史 = 从教机器规则，到让机器自己学习」；悬念：读了半个互联网的 GPT-3，脑子里到底在算什么？→ 下讲解剖 | ✍️ 门票卡：写下一个没听懂的词 |

**课后轻量体验：** [01_ai_basics.ipynb](../../quick_start/cann_basics/01_ai_basics.ipynb) 前半（AI 发展历程 / AI·ML·DL / 模型 / 训练与推理），在线运行即可——内容与本讲"来龙去脉"逐段对应。

### 第 2 讲｜什么是大模型，大模型在算什么？（45'）

| 时段 | 环节 | 要点 | 互动设计 |
|------|------|------|---------|
| 0–5' | 开场游戏「猜下一个字」 | 「今天天气真＿＿」「我去食堂吃＿＿」全场齐喊答案 → **人脑也在预测下一个词**；ChatGPT 玩的就是同款游戏，只是玩了亿万次 | 🗳️ 全场齐答 |
| 5–16' | 问题一：什么是大模型？ | 上讲悬念接续——"大"在哪三处：**数据大**（数万亿 token 语料）、**参数大**（千亿级）、**算力大**（千卡集群训练数月）；参数 = 模型从语料里记下的"规律"；Transformer 注意力 = 自动划重点（回访第 1 讲，仍只讲直觉） | 复习式提问 |
| 16–30' | 问题二：大模型在算什么？ | 本质 = **概率计算器**：每生成一个字 = 预测「下一个 token 的概率分布」再掷骰子挑选；token 切分游戏（一句话怎么切词）；一次回答 = 成千上万轮「矩阵乘法 + 概率选择」；训练 = 在海量文本上做万亿道"完形填空" | 白板共创 token 切分 |
| 30–40' | 亲眼看见概率 | 演示 / 视频：大模型逐字"蹦字"输出——那就是一个一个 token 在生成；彩蛋：同一问题问两遍答案不同（因为每次都在"掷骰子"）；算力账单（量级）：单次大模型训练 = 千卡级集群 × 数月 × 百万度级耗电 | 🔬 现场演示 |
| 40–45' | 收束 + 悬念 | 一句话带走：「大模型 = 一台吃算力的概率机器」；悬念：这张算力账单，你手里的 CPU 买得起单吗？谁来养活它？→ 下讲 | ✍️ 门票卡 |

**课后轻量体验：** [01_ai_basics.ipynb](../../quick_start/cann_basics/01_ai_basics.ipynb) 后半（常见架构 / 计算图 / 算子 / 张量）；用任意大模型 App 完成一次对话，观察"逐字生成"节奏并数一秒大约蹦几个字。

### 第 3 讲｜NPU 与 CANN：谁来支撑人工智能算力？（45'）

| 时段 | 环节 | 要点 | 互动设计 |
|------|------|------|---------|
| 0–5' | 开场竞猜「你的笔记本训练 GPT-3 要多久」 | 选项竞猜：数月 / 数年 / 数十年 / 上万年？→ 揭晓：**上万年级**（认知冲击）；而千卡集群只需数月——差距来自哪里？ | 🗳️ 竞猜抢答 |
| 5–15' | 问题一：为什么通用 CPU 养不起大模型？ | CPU = 全能教授（什么都会，但每门课都不是最快）；大模型负载画像——计算高度重复，核心是海量的矩阵乘与向量运算；CPU 三重困境：通用核数量少（几十个 vs 加速器成百上千计算单元）、为通用逻辑而非大规模并行设计、算力 / 功耗比低（功耗墙） | CPU vs 加速器对比表 |
| 15–27' | 问题二：NPU 为什么快？ | 术业有专攻：餐馆比喻（CPU = 店长管全局调度，NPU = 后厨大灶管爆炒）；**异构计算** = Host / Device 分工，CPU 与 NPU 各干擅长的事；NPU 内部一瞥：达芬奇架构三核异构（Cube 矩阵单元 = 磨盘 / Vector 矢量单元 = 排刀 / Scalar 标量单元 = 主厨）＋多核大规模并行；GPU 与 NPU 一句话对照（都做并行，NPU 为 AI 负载更专用） | 类比 + 架构图 |
| 27–40' | 问题三：CANN 如何支撑算力？ | 光有芯片不够——NPU 听不懂 PyTorch，需要"翻译官 + 管家"；**CANN = 昇腾 NPU 的异构计算软件栈**（生态位对标 CUDA）；分层一图：框架适配（torch_npu 等）→ 图引擎 → 算子库 → Ascend C → 编译器 / 运行时 / 驱动；"一行代码的旅程"：`import torch_npu` 一行改动，既有 PyTorch 代码自动跑在 NPU 上；演示 / 视频：同一矩阵乘 CPU vs NPU 性能对比 | 🔬 现场演示 |
| 40–45' | 全课收束 | 三问回收：AI 怎么来的（七十年演进）→ 大模型在算什么（概率机器）→ 算力谁来支撑（NPU 硬件 + CANN 软件栈）；金句：**「AI = 算法 × 算力 × 软件栈，三者缺一不可」**；学习出口：cann_basics 自学课 → 启航营 → 学分课程体系 | ✍️ 一分钟纸：写下最想继续了解的一个问题 |

**课后轻量体验（任选其一）：** [02_what_is_npu.ipynb](../../quick_start/cann_basics/02_what_is_npu.ipynb) / [03_what_is_cann.ipynb](../../quick_start/cann_basics/03_what_is_cann.ipynb) / [04_npu_practice.ipynb](../../quick_start/cann_basics/04_npu_practice.ipynb)（在线 Notebook，无需本地环境）。

## 七、学习出口与课程衔接

完成本课程后的推荐路径：

```
AI 通识课（本课程，2.25h，建立全景认知）
  → quick_start/cann_basics 完整自学课（4 个 Notebook + 2h 课件，零基础）
    → 启航营（一天 / 两天 / 8 次课，动手开发第一个算子）
      → 新增课程体系（数据科学 / 深度学习 / 生成式 AI / 加速计算等学分课）
```

- 与 **cann_basics** 的衔接：本课程三讲即 cann_basics 四个 Notebook 的"讲座版导读"，课后体验直接复用其内容；
- 与 **启航营** 的衔接：第 3 讲 NPU / CANN 内容为启航营第 1 讲（昇腾 AI 产业生态与 CANN 架构基础）的轻量预演；
- 与 **传统课程** 的衔接：第 1 讲 AI 演进史可衔接《深度学习》课程导论，第 3 讲体系结构内容可衔接计算机组成原理 / 体系结构课的 CANN 融入单元。

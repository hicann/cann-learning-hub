## 一、融入策略总纲（借鉴 CUDA 五模式）

> 完整模式分析见竞分报告第 2 节（M1–M5）；本规划面向传统课，主用后四种"外挂式"模式：

|------|---------------------|---------|

- **教材席位**：国内主流计组教材（唐朔飞/袁春风等）无 NPU/GPU 内容 = 空位；借 101 计划新编教材序列写入"达芬奇 NPU 案例小节"（对标 Kirk & Hwu 写 COD 附录的路径）

## 三、主要课程 1.2：计算机体系结构（本科高年级/研究生，13 次大课 × 135 分钟 ≈ 39 学时）

### 3.2 课次 9：第一幕·需求评审会——大模型到底要什么（CANN 主讲 1）

> **设计总纲：从体系结构出发，回到体系结构**——用第 1–3 章的工具箱分析新负载，产出甲方需求清单；CANN 作为"架构决策的软件面证据"出现。
> **本课角色设计**：学生 = **需求评审团**；产出物 = **甲方需求清单**（贴墙保留三节课，第 2 节课逐条验收）。
> **业界蓝本**：CMU 15-418（workload 特征先行）、Berkeley CS267（Roofline 定量）、课件标准（钩子/互动/行动出口）。

#### 3.2.0 两个通用工具箱（三节课统一规则，开课先立规矩）

**问题引导六法**（"怎么引导出问题"的操作答案）：

| 手法 | 操作要点 | 本节应用例 |
|------|---------|-----------|
| **数量级竞猜** | 全班先猜数字→举手分档→再揭晓，制造"哇"时刻 | "GPT 回你一句'你好'，做了多少次乘加？"（A.1e6 B.1e9 C.1e11 D.1e13） |
| **认知冲突** | 并列两个"不该共存"的事实，逼学生找解释 | "同一个 GELU 算子，3ms 和 0.3ms——差的 10 倍谁偷走的？"（第 3 节课开场） |
| **苏格拉底追问链** | 连续三问，每问只前进一小步；最后一问**不给答案** | "CPU 跑大模型哪些模块在摸鱼？→摸鱼的能裁吗？→裁掉后谁来干它的活？"（第三问写上黑板角落，第 3 节课揭晓——**全章悬念①**） |
| **角色代入** | 把学生放进决策者位置 | "你是架构师，100mm² 预算怎么花？" |
| **反事实** | 假设某技术不存在，倒推其必要性 | "没有 Tensor Core，GPT-4 训练要多久？" |
| **甲方乙方** | 把技术指标戏剧化为商务冲突 | "甲方：要百倍算力、毫秒响应、还不能贵——乙方（你）怎么回？" |

**研讨五式**（"怎么研讨"的操作答案）：

| 式 | 适用 | 流程（时间盒严格，计时器投屏） |
|----|------|---------------|
| **结构化辩论** | 有两可答案的判断题 | 发证据卡→5' 组内立论→3'+3' 双方陈词→5' 自由辩→3' 评审团→2' 教师裁决（**给分类框架，不给对错**） |
| **白板共创+画廊漫步** | 设计类开放题 | 10' 小组白板画→5' 挂墙互访互问→对比真实方案找差距 |
| **病历诊断** | 优化/排错类 | 发"病历"（剖析报告+代码）→诊断→开药→预后→当堂揭晓对照 |
| **Think-Pair-Share** | 轻量快问 | 1' 独立写→2' 同桌互查→随机点名 |
| **竞猜抢答** | 注意力低谷调节 | 手势表决（✋对/🙌错）或分档举手 |

> 研讨成功五要素：**问题可辩**（无标准答案）、**素材对等**（每方有证据卡）、**产出可见**（白板/一分钟纸存档）、**时间盒严格**、**裁决给框架不给答案**。

#### 3.2.1 段一（0–45'）：当我们讨论大模型，具体在讨论什么

| 时间 | 环节 | 设计细节 |
|------|------|---------|
| 0–5 | 🪝 **三连数量级竞猜** | 逐题举手分档再揭晓：①一次"你好"的乘加量（≈1e11）②175B 参数 ≈ 多少本书（≈数千本）③GPT-3 训练一次耗电（≈1200 户家庭/年）。**每题揭晓后追问一句"所以瓶颈会在哪？"**——只制造体感，不收答案 |
| 5–15 | **甲方画像 5W1H** | 大模型 = Who（Transformer 家族）/ What（本质 = 海量矩阵乘 + 概率采样的循环）/ When（**训练=月级集群 vs 推理=毫秒级——同一负载两副面孔**）/ Where（数据中心的电表上）。引导语："你们天天用它，但谁看过它的计算图？今天当一次'验房师'" |
| 15–30 | **计算特征：白板共创算子 DAG** | 教师画 Transformer Block 骨架，**学生报算子名、教师填**（预期：MatMul/Softmax/Add/LayerNorm/Attention…）；归纳四类：**MatMul（60%+ FLOPs、形状静态规整）/ Attention（复合型）/ Elementwise（低算术强度）/ Reduce（归约）**。互动点：报对打响指凑齐全家福，随后投票"哪类占绝大多数 FLOPs？" |
| 30–45 | **存储特征：三种货物的仓库课** | 比喻+追问：**权重=常驻户**（只读反复复用）/ **激活=快递**（到站即走）/ **KV Cache=越住越多的长租客**（随序列线性膨胀）。追问链："推理到第 10000 个 token 谁吃光内存？→ 为什么没人提前告诉你？"（引出 KV 管理 = 架构级问题，为第 3 节 PD 分离与第 5 章互联埋线） |

#### 3.2.2 段二（50–95'）：访存特征与 CPU 的困境

| 时间 | 环节 | 设计细节 |
|------|------|---------|
| 50–65 | **访存特征：用第 3 章语言"验伤"** | 三种访存模式逐一判定与 Cache 关系：权重=强时间局部性（Cache 友好）/ 激活=流式空间局部性（预取友好）/ **KV=局部性差（Cache 杀手）**。随后 **Roofline 现场手算**（分组）：GEMM [4096]³、Add、Softmax 的 AI 值→投票归类 bound→结论落成甲方需求第 1 条："**算力与带宽要分别喂饱两类算子**" |
| 65–80 | **CPU 的困境：苏格拉底三连问**（本课核心引导） | ①"CPU 跑 GEMM 时，哪些模块在摸鱼？"（分支预测器、乱序窗口、大 Cache——逐一点名）②"摸鱼的能裁吗？"（能——负载静态可知）③"**裁掉后谁来干活？**"（**不答，写上黑板角落，宣布第 3 节课揭晓**——悬念①）。顺势讲功耗墙与 Amdahl：单核加速比已死，并行是唯一活路 |
| 80–95 | **CPU→GPU SIMT 演进：偶然中的必然** | 先讲 GPU **为图形而生**（数千像素天然并行——它本来不是为 AI 设计的），再讲 AlexNet 时刻（2012，历史包袱变红利）；SIMT 三件套：warp 锁步/海量线程容忍延迟/分支发散代价。**对照锚点**：第 2 章 O3 用 ILP"消除"延迟 vs GPU 用 TLP"容忍"延迟——同一问题的两种哲学 |

#### 3.2.3 段三（100–135'）：辩论研讨「SIMT 是不是最终编程形态？」

| 时间 | 环节 | 设计细节 |
|------|------|---------|
| 100–125 | 🗳️ **结构化辩论**（本课压轴，辩题 = 大纲原题激活） | **辩题**："从 CPU 到 GPU SIMT，是不是 AI 计算的终点？"<br>**正方证据卡**：CUDA 生态壁垒 10 年积累 / 动态 shape 新算子只有 SIMT 灵活 / 图形+AI+科学计算一卡通吃<br>**反方证据卡**：能效差约一个量级 / 大模型负载 90% 静态（摸鱼的又回来了）/ Tensor Core 的出现 = GPU 自己已在"背叛"SIMT<br>**流程**：5' 组内立论→3' 正方陈词→3' 反方陈词→5' 自由辩→3' 学生评审团投票陈词<br>**教师裁决框架**（关键：给分类不给对错）："判断标准 = **负载确定性**——动态负载 SIMT 灵活性胜，静态负载专用单元能效胜。那能不能**两个都要**？下节课看华为工程师怎么回答这个辩题。"（**悬念② → 第 2 节课 SIMD/SIMT 双模式**） |
| 125–133 | **GPU 架构演进概述** | Fermi→Volta（Tensor Core 诞生）→Hopper，讲成"**GPU 长出专用单元的三部曲**"——为辩论的"背叛"论提供实证，也为达芬奇 Cube 铺垫："GPU 里的 Tensor Core，就是达芬奇 Cube 的表哥" |
| 133–135 | 🚪 **行动出口** | 课后跑 PyTorch profiler 或 msprof 剖析任意模型，交"**我的甲方需求清单**"（算子 Top3 + 各自 bound 类型 + 一条最想说给芯片设计师的话）——**下节课这份清单就是评审材料** |

**带走能力**：能用局部性/AI 值分析任一 AI 算子；能陈述大模型对现代 CPU 的三大挑战。
**映射原子课**：L1-01（算子概念）、L1-02 节选（异构平台）、L2-05 节选（融合动机）。

### 3.3 课次 10：第二幕·方案评审会——CANN/达芬奇如何接单（CANN 主讲 2，全章主体）

#### 3.3.2 段二（50–95'）：维度二存储 + 维度三搬运

| 时间 | 环节 | 设计细节 |
|------|------|---------|
| 50–75 | **维度二：从自动挡到手动挡**（全章最好用的隐喻） | **CPU Cache = 自动挡**（预取/替换/一致性全自动，舒适但有迟滞费油）；**达芬奇 UB/L1/L0A·B·CA = 手动挡赛车**（每一挡程序员自己换——Tiling 切块/双缓冲/复用规划）。抛出**三机制去向对照表**（全章核心一张表）：硬件预取→软件 Tiling（DataCopy）/ 硬件替换→UB 复用规划 / 硬件一致性→asc_lock·asc_mem_bar 同步原语——判断依据回链课次 9："**负载静态可知 → 在线猜测不如编译期规划**"。**CANN 融入**：`__gm__/__ubuf__` 地址空间限定符 = **ISA 直接暴露存储层次**；TQue 双缓冲 = **把第 2 章流水线重叠做成 API 一等公民**（搬第 N+1 块的同时算第 N 块——流水段从指令变成数据块） |
| 75–95 | **维度三：数据搬运——对齐/非对齐/ND-NZ/NDDMA 的"快递规则"** | 讲法 = 快递公司运营规则：**32B 对齐 = 标准托盘**（批量装车才划算，非对齐 = 零担，贵）；**ND/NZ Layout = 分区编号的货架**（块内连续、块间跳步——正是 Cube 爱吃的形状）；**NDDMA = 会认路的老司机**（多维搬运一次指令搞定：取子块+补边 Pad+Transpose）。**互动：Think-Pair-Share**——"要搬 [H,W] 图像中间一行并左右各补 2 列，你给 DMA 下什么单？"（1' 独立写→2' 同桌互查→点名） |

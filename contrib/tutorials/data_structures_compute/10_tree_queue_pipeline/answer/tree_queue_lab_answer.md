# 第 10 章实验解析

## 1. 为什么先用 BFS

`parent` 数组把树的连接关系压缩成整数索引。BFS 使用 FIFO 队列从根节点开始逐层释放任务，因此可以同时得到 `depth` 和 frontier。对于树依赖，只有父任务完成后，子任务才能进入就绪队列。

## 2. 为什么还要使用优先队列

FIFO 能保证依赖顺序，但不区分不同分支后续还有多少工作。参考实现从叶子向根累计 `subtree_work`，把“剩余子树工作量”作为优先级。每次弹出一个已经就绪的任务，再把它的子节点放入堆中。堆中的任务始终满足父节点已完成这一约束。

## 3. 如何观察流水线重叠

每个任务依次经历：

```text
CopyIn -> Compute -> CopyOut
```

`pipeline_schedule` 使用 `queue_depth=2` 表示两个可复用的缓冲槽，使用 `compute_lanes=2` 表示两个并行 Compute lane。输出中的 `events` 保存每个节点三个阶段的时间区间，可以据此检查：

- Compute 必须在 CopyIn 完成后开始；
- CopyOut 必须在 Compute 完成后开始；
- 缓冲槽被再次使用前，上一项的 CopyOut 必须结束；
- 依赖关系由调度顺序保证，而不是由流水线时间模拟额外放宽。

## 4. 结果应如何判断

不要只比较最终耗时。至少同时检查：

1. 调度结果是否包含全部节点且没有重复；
2. 每条父子边是否满足父节点先于子节点；
3. FIFO 和优先级顺序是否确实不同；
4. 每个任务的三个阶段是否严格按顺序；
5. 改变 `queue_depth`、`compute_lanes` 或节点耗时后，结论是否仍符合资源约束。

默认数据下，优先级顺序会优先展开剩余工作量较大的分支，因此在本实验的双缓冲、双 Compute lane 配置下，端到端时间略短。这个数值只用于验证模拟器逻辑，不代表特定 Ascend 设备上的实际性能。

## 5. 向 Ascend C 迁移

设备侧实现时，可以把一个 frontier 的节点属性整理为连续 Tensor，通过 TQue 在 CopyIn、Compute 和 CopyOut 之间传递；Host 侧保留树的父子索引、堆的调整和 frontier 边界控制。迁移后的验证应分开记录：依赖顺序正确性、Tensor 数值正确性、流水线阶段事件以及设备端性能。

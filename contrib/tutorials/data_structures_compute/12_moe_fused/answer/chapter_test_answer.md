# 第 12 章知识测验 — 参考答案与解析

## 选择题

### 题目 1：答案 B

融合的本质是子图压缩：三个中间张量（scores [N,E]、gate_scores [N,E]、
topk_scores [N,K]）在 4 算子序列中各经历一次"写 GM + 读 GM"，
合计 16·N·E + 8·N·K 字节（2 字节元素）；融合后它们全部驻留 UB，
GM 流量清零。x / W 的读取与最终输出的写回在融合前后不变。

### 题目 2：答案 B

K 轮 "取最大 + 掩蔽" 是选择类算法（selection）：每轮线性扫描 E 个元素取最大，
共 K 轮，复杂度 O(K·E)，与 K 无关的排序代价。Top-K 是选择问题而非排序问题——
只需"前 K 个"，不需要全序。E ≤ 32、K ≤ 8 时 K 轮 max 是最朴素且足够快的选择。

### 题目 3：答案 B

910B 上 kernel 的标量 GM 写（SetValue）经 L2 缓存（line=64B）。
多核并发写同一条 line 时，核间没有写一致性/原子 RMW 保证，
先写入的核可能被后写入的核覆盖（或部分字节丢失），表现为非确定性的输出错误。
修复方式是切分上保证每条 line 只被一个核写入（连续块 + 64B 对齐）。

### 题目 4：答案 C

K=2：2K=4，gcd(4,64)=4，R_align = 64/4 = 16 行。
含义：16 行的 wt 输出 = 16×(2×2) = 64B 恰为一条 line；
idx 输出 = 16×(2×4) = 128B = 两条 line，同样对齐。

### 题目 5：答案 B

开发历程中，向量路线（路线 B）实测发现向量 Cast 指令不支持 BF16↔FP32
（"not support bf16 type cast"），接口改为 FP16 并重新生成了测试数据；
最终的纯标量路线沿用 FP16，与数据、参考实现和第 8 章保持一致。
（纯标量下 C++ 类型转换不依赖向量指令，理论上可以支持 BF16，属可选扩展。）

## 填空题

### 题目 6：64

`kernel_utils_constants.h` 中 `const uint32_t CACHE_LINE_SIZE = 64;`。

### 题目 7：≤（不超过）；跨核

融合可行性判据：中间张量按行分块后容量 ≤ 单核 UB（192KB），
且切分维度上无跨核依赖（本算子按 token 行切分，逐行独立）。
反例：E 极大（单块超 UB）或 softmax 需要全局归一（跨行/跨核依赖）。

### 题目 8：4；1

matmul、softmax、topk、div 四次发射合并为 1 次。
小 N 场景下发射/调度开销占比高（4 算子序列约 0.22~0.31ms 中计算占比 < 10%），
发射次数减少是融合在小 N 下的主要收益。

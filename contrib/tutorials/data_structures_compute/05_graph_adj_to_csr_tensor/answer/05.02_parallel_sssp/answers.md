# 05.02 课后思考答案

1. Pull 按目标顶点切分：一个 Core 只计算并写回自己负责的 `dist_out[v]`，每个输出元素在一轮中只有一个写入者，因此不需要 `AtomicMin`。Push 则按源顶点或源边遍历，多个不同源顶点可能同时尝试松弛同一个目标顶点，因而通常存在写冲突。
2. 不能。`65536` 个 `float32` 距离值本身就需要 `256 KiB`，已经超过 `192 KiB` UB，更没有空间容纳行偏移、边块和输出。应让完整的双距离数组继续驻留 GM，每个 Core 只在 UB 中保留当前目标顶点块和边块；对源点距离按需从 GM 分块搬运或缓存，而不是复制完整距离快照到 UB。
3. Host 每轮同步保证所有 Core 都写完 `d^(k+1)` 后才交换输入、输出缓冲区。若不同步，下一轮可能读取尚未完整写好的距离数组，破坏同步 Bellman-Ford 的轮次语义。
4. 幂律图中少数目标顶点可能拥有大量入边。即使每个 Core 分到相同数量的顶点，负责高入度顶点的 Core 仍会处理远多于其他 Core 的边，形成长尾和负载不均。可按 CSR 的边数前缀和切分工作量，或将超大行进一步分块，并在需要时采用动态任务队列。

# 实验二：算子原型参考答案

以下以 Sinh 算子为例。选择其他基础算子时，应保持相同的接口说明结构。

## 1. 接口定义

| 项目 | 参考说明 |
| --- | --- |
| 算子名称 | `Sinh` |
| 输入 | 张量 `x`，支持课程样例中声明的 dtype 和 format |
| 输出 | 张量 `y`，Shape 与输入一致，dtype 与输入一致 |
| 属性 | 无 |
| Shape 推导 | `y.shape = x.shape` |
| Type 推导 | `y.dtype = x.dtype` |
| 计算语义 | 对每个元素计算双曲正弦函数 |

实际支持的 dtype、format 和维度范围应以当前 CANN 算子定义及运行验证结果为准。

## 2. 跨生态接口对比

| 维度 | CANN OpDef | PyTorch `torch.sinh` | ONNX `Sinh` |
| --- | --- | --- | --- |
| 接口形式 | 显式声明输入、输出及约束 | Python 张量 API | 计算图算子节点 |
| Shape 关系 | 在原型中声明或推导 | 运行时按输入张量传播 | 输出 Shape 与输入一致 |
| dtype 约束 | 由算子原型和实现共同限定 | 由框架和后端能力决定 | 由算子规范及后端实现决定 |
| 硬件相关约束 | 可表达 format、dtype 等硬件适配要求 | 高层接口通常隐藏后端细节 | 主要描述框架无关计算语义 |

## 3. 异常场景测试

| 用例 | 输入 | 预期检查 |
| --- | --- | --- |
| 正常输入 | 支持的 dtype，常规 Shape | 输出 Shape、dtype 正确，数值与基准一致 |
| 空张量 | Shape 中包含 0 | 行为与算子约束一致，不发生越界访问 |
| 不支持的 dtype | 使用原型未声明的 dtype | 原型校验或运行阶段给出明确错误 |
| 极端数值 | 较大正数、较大负数、0 | 检查溢出、无穷值及数值误差 |
| 高维输入 | 接近实现支持上限的维度 | 正确推导 Shape，超限时给出明确错误 |

## 4. 完成标准

提交内容应同时包含接口表、Shape/Type 推导规则、跨生态差异和至少三类异常用例。不能只列 API 名称，也不能把未经运行验证的 dtype 或 format 写成已支持能力。

# 实验四：Kernel侧开发与性能分析参考答案

## 1. 三阶段数据流

```mermaid
flowchart LR
    GM1[Global Memory输入] -->|DataCopy| CI[CopyIn]
    CI -->|EnQue/DeQue| C[Compute]
    C -->|EnQue/DeQue| CO[CopyOut]
    CO -->|DataCopy| GM2[Global Memory输出]
```

- `CopyIn`：从 Global Memory 搬运输入到 Local Memory，并通过队列管理可计算的数据块。
- `Compute`：从输入队列取得 LocalTensor，执行 Add、Mul 等计算，再把结果放入输出队列。
- `CopyOut`：从输出队列取得结果并搬回 Global Memory，随后释放 LocalTensor。

`TPipe` 管理流水线资源，`TQue` 协调阶段间的数据生产与消费，`GlobalTensor` 表示外部存储中的张量，`LocalTensor` 表示 AI Core 本地 Buffer 中的张量。

## 2. 功能验证记录模板

| 检查项 | 记录内容 |
| --- | --- |
| 测试环境 | NPU 型号、镜像、CANN 版本、Python 内核版本 |
| 输入规模与 dtype | 填写实际测试配置 |
| 基准实现 | 说明 CPU、NumPy 或框架基准 |
| 误差指标 | 最大绝对误差、最大相对误差或课程指定指标 |
| 容差 | 填写与 dtype 相符的阈值 |
| 验证结论 | 通过或失败；失败时附定位记录 |

验证结论必须来自实际运行。参考答案不提供虚构的“通过”结果。

## 3. 性能采样记录模板

| 指标 | 实测值 | 分析用途 |
| --- | --- | --- |
| msProf 输出目录 | 填写本次 `prof_result` 实际路径 | 绑定本次采样证据 |
| 性能汇总文件 | 填写实际 `op_summary_*.csv` 路径 | 便于复核原始记录 |
| 算子名称列 | 填写 CSV 实际列名与 Add 相关记录 | 确认分析对象 |
| 耗时列 | `Task Duration(us)`、`Duration(us)` 或本环境实际列名 | 统计调用耗时 |
| 调用次数与耗时统计 | 填写记录数、均值、最小值和最大值 | 观察运行波动 |

不要预设 `summary.txt`、`op_execute_time`、`aicore_utilization` 等字段存在。CANN 版本不同，输出目录和 CSV 列名可能变化，应先读取本次生成的真实表头。

## 4. 瓶颈判断

- `op_summary` 中的任务耗时可用于确认算子调用和比较同环境下的不同版本，但单独的耗时值不能证明 Compute-bound 或 Memory-bound。
- 判断 Compute-bound 需要计算流水或计算单元指标；判断 Memory-bound 需要内存带宽、搬运或流水等待指标。
- 如果本次只启用了 `--task-time=on`，报告应写为“完成耗时观察，瓶颈类型待进一步采样”，不能使用模拟利用率下结论。

最终报告应给出“实际文件 -> 实际字段 -> 数值统计 -> 证据允许的结论”。需要继续优化时，再增加相应硬件指标采集，并比较调整 tile 大小、并行度或搬运方式前后的同口径结果。

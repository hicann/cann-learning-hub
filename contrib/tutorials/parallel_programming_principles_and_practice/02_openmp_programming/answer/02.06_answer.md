## 四类考核参考答案

### 1. 客观题

答案：（1）C。`row_ptr[rows]` 是最后一行区间的结束哨兵，恒等于矩阵的非零元总数 nnz。（2）对。第 r 行只写 `y[r]`，任意两行 r1≠r2 的写目标 `y[r1]` 与 `y[r2]` 下标不同，`parallel for` 按行并行天然无写冲突，不需要原子操作或锁；x 的读取可能重叠但只读不写，也不需要同步。

### 2. 简单题

处理方法：`cd src/openmp_spmv` → `bash scripts/build.sh`；固定矩阵与 repeat（例如 `--repeat 3`），依次用 `OMP_NUM_THREADS=1,2,4,8`（环境允许时含 16）运行 `bash scripts/run.sh`，CSV 分别输出。证据字段：Threads、CPU single、OpenMP、Speedup、Error（相对误差低于工程门槛如 `1e-6` 视为通过）。串行 reference 取 OMP_NUM_THREADS=1 的 CPU single 输出。判定条件：命令可复现、结果表字段齐全、Error 达标、唯一变量为线程数。

### 3. 中等题

处理方法：固定矩阵、线程数（如 4）与 repeat，分别以 `OMP_SCHEDULE=static` 和 `OMP_SCHEDULE=dynamic,16`（可再选 guided）各运行一次，比较 OpenMP 耗时与并行效率。行 nnz 长尾明显的矩阵上 dynamic 通常改善负载均衡，但引入调度开销，效率可能上升、持平或下降，不能预设结论。证据字段：Schedule、OpenMP、Speedup、并行效率，并说明矩阵生成参数所决定的行结构。判定条件：唯一变量是 schedule，其余参数（矩阵、线程数、repeat、容差）一致，结论引用实测数字。

### 4. 困难题

处理方法：对 1/2/4/8（可到 16）线程分别记录 T_p，计算 S_p=T_1/T_p、E_p=S_p/p；估算每线程有效读带宽 ≈（value/col_idx 读入字节 + 间接 x 读入字节）/T_p，观察其随线程数是否趋于饱和。平台期证据：E_p 明显下降而带宽接近稳定 → bandwidth-bound；若某点加速明显低于带宽模型，再检查每行 nnz 方差（负载不均）与动态调度的额外开销。判定条件：给出计算过程、平台期出现位置与所用字段，结论能区分三类原因（带宽饱和/负载不均/调度开销）。

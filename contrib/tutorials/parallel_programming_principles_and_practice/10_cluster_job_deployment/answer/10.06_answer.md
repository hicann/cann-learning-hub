# 参考答案

完整报告应证明 vendored dependency 被使用、构建产物存在、输入来源明确、三个 solver 正常退出并收敛、CSV 可解析；同时分别解释 assembly、linear solver、SpMV 和 total，不把 wrapper 结果扩大为完整 Xyce 集群仿真。


## 参考实验操作

实验必须基于 `src/ascend_xyce/`。确认 vendored backend 后离线 build；用环境变量和 `--matrix` 改一个配置；检查三种 solver 的 converged、residual、solution error，并保存 CSV/log。

建议记录表：

| Matrix | Solver | Linear/Simulation | Iterations | Residual | Converged | Error |
|---|---|---|---|---|---|---|
|  |

分析时先判断退出码、正确性和可比性，再解释性能变化。若环境缺少 CANN、MPI 或多设备，应提交明确的诊断证据，不得把历史 CSV 冒充本机运行结果；参考答案不规定固定耗时。

## 四类考核参考答案

### 1. 客观题

答案：（1）A。`LinearSolverKind` 枚举为 `CpuSingle`、`CpuOpenMP16`、`AscendDevice`，不存在其它 Device 枚举名。（2）对。active Device solver 由 CMake 目标 `xyce_npu_solver` 直接编译第 07 章 `dis_gmres` 源码（`DIS_GMRES_ROOT`），`XyceLinearSolverAdapter::solve` 调用 `dis_gmres::distributed_gmres`；vendored `backend/gmres/Ascend-GMRES` 只提供 CPU baselines 与 legacy Host prototype 源码，其 `npu_spmv.cpp` 文件名不是 active `AscendDevice` 的 NPU 证据。（3）B。CSV 文件整体只写 1 行表头；每个被选矩阵贡献 3 行 solver 数据（CpuSingle、CpuOpenMP16、AscendDevice）。未知 `--matrix` 名称会在打开/截断 CSV 之前被拒绝并返回非零（退出码 2），已有 CSV 不被覆盖；运行结束后还会校验 CSV 行数（每矩阵 3 行），只写表头或行数不符返回非零。（4）对。wrapper 不解析 netlist、不运行 Xyce executable，不能得出完整 netlist 仿真或集群/MPI 调度行为结论；其能得出的结论是依赖与构建链路、三种 solver 的正确性与端到端时间、CSV/log 字段。

### 2. 简单题

处理方法：给出离线构建命令（如 `ASCEND_XYCE_FETCH_XYCE=0 bash scripts/build.sh`）与 vendored backend 门禁证据（CMake/构建日志中链接或启用的输出），运行命令（如 `ASCEND_XYCE_WARMUP=0 ASCEND_XYCE_REPEAT=1 bash scripts/run.sh --matrix U1 --csv results/...`），保存 stdout/stderr 日志；CSV 应含三个 solver 行，每行 converged=1、residual 低于阈值（`<1e-6`）、error 达标（相对 `expected_solution` 与相对 CPU reference 的解误差均 `<1e-3`，与 `kSolutionErrorTolerance` 一致；任一超限 benchmark 以非零退出且不写该行）。判定条件：构建/运行/日志/CSV 四类证据齐全，三个 solver 均收敛。

### 3. 中等题

处理方法：用 CSV 字段把总时间分解为 matrix assembly、linear solver 与其中 SpMV 等阶段，说明哪些属于 wrapper 计时口径、linear solver 与总模拟时间为何不同。失败场景：给一个不可写结果目录（或未知参数），运行并保存错误日志，按错误文本定位层次——参数解析（usage/unknown argument）、构建（CMake 失败）、运行（设备/依赖失败）或结果写回（CSV 打不开）。判定条件：分解与计时口径正确，失败被复现并归因到具体层次。

### 4. 困难题

处理方法：审计并列出依赖与构建门禁证据（vendored backend 被编译/链接的 CMake 输出或源码包含关系）、输入矩阵来源（`matrices/*.csrbin` 或生成）、CSV/log 完整路径与内容校验（行数、字段、converged/residual 门槛）。设计验收脚本步骤（不修改仓库）：构建 → 以 `ASCEND_XYCE_WARMUP=0` 运行 → 解析 CSV 三行 → 校验收敛与误差 → 输出 PASS/FAIL。说明换机器或换 upstream 版本后，依赖路径、门禁结果、性能数字与 solver 语义都需要重新验证。判定条件：证据链完整、脚本步骤可复现、边界说明清晰。

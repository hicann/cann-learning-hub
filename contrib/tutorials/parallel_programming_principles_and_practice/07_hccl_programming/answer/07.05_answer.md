# 参考答案

表格至少记录 rank、collective、transfer、local SpMV（`local_spmv_launch_to_complete_ms`）、total、error。结论不能把 local SpMV 时间与端到端 total 混用，也不能使用 AI Core SpMV speedup 表述。端到端 total 与各阶段汇总必须是跨 rank 的 MAX 聚合（关键路径 wall time，输出为 `Total Time (MAX across ranks)` 等字段），不能把 SUM/world_size 的 rank 均值当作 wall time；每 rank 另有 `Local ...` 本地摘要供核对。


## 参考实验操作

实验必须基于 `src/hccl_spmv/`。用实际 server/device IP 运行 `generate_rank_table.py`（仅接受 `--server-ip`/`--device-ip`/`--output`，`device_id`/`rank_id` 按地址顺序自动生成），strict real 模式构建后用 `run.sh`/`run_scaling.sh` 改 Rank 数；2/4 rank 分别使用各自匹配的 rank table（`rank_table_2p.json`/`rank_table_4p.json`），不要用一个 4-rank JSON 配合 `--npus-list 2,4`，也可不传 rank table 走单机 root-info fallback；检查 `rank_*.log`。`run.sh` 聚合输出按 rank 顺序带 `===== rank N =====` 标题回放每个 rank 的完整日志，`run_scaling.sh` 的每个 case 日志（`results/<matrix>_<n>npu.log`）因此保留全部 rank 证据。合格日志必须同时显示 `Actual Compute Backend=Ascend C FP32 RTC` 与 `Communication Backend=ACL+HCCL`。

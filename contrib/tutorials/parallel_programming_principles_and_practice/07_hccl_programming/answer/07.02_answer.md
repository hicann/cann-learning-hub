# 参考答案

每个 rank 唯一映射到 device；所有进程共享 world size 和同一 communicator 配置。检查设备可见性、IP、rank table size、root-info 文件和超时。


## 参考实验操作

实验必须基于 `src/hccl_spmv/`。用实际 server/device IP 运行 `generate_rank_table.py`（仅接受 `--server-ip`/`--device-ip`/`--output`，`device_id`/`rank_id` 按地址顺序自动生成），strict real 模式构建后用 `run.sh`/`run_scaling.sh` 改 Rank 数；2/4 rank 分别使用各自匹配的 rank table（`rank_table_2p.json`/`rank_table_4p.json`），不要用一个 4-rank JSON 配合 `--npus-list 2,4`，也可不传 rank table 走单机 root-info fallback；检查 `rank_*.log`。合格日志必须同时显示 `Actual Compute Backend=Ascend C FP32 RTC` 与 `Communication Backend=ACL+HCCL`。

建议记录表：

| Ranks | HCCL | Transfer | Local NPU SpMV | Total | Error | 日志 |
|---|---|---|---|---|---|---|
|  |

分析时先判断退出码、正确性和可比性，再解释性能变化。若环境缺少 CANN、MPI 或多设备，应提交明确的诊断证据，不得把历史 CSV 冒充本机运行结果；参考答案不规定固定耗时。

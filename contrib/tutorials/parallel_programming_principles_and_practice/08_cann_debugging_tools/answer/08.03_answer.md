# 8.3 参考答案

## 一、客观题

1. memcheck=越界访问；racecheck=流水线数据竞争；initcheck=读取未初始化数据；synccheck=同步事件不配对。
2. 独立 ASC 使用目标级 `target_compile_options(... --sanitizer)`；标准工程通过
   `add_ops_compile_options` 或 `npu_op_kernel_options` 给 Kernel 加 `-sanitizer`。
3. 不等于。还必须匹配当前 MODE 的核心诊断，并记录日志、源码位置和退出码。
4. `BLOCKED`。
5. 错。课程不执行 `sudo/chmod/chown`，也不写 `/proc/debug_switch`。

## 二、简单题

memcheck 日志必须包含 illegal read/write 或越界签名，并输出类似：

```text
SIMPLE_STATUS=EXPECTED_DIAGNOSTIC mode=memcheck exit_code=<实际值> log=<实际路径>
```

退出码没有固定答案，必须取本次工具返回值。

## 三、中等题

两种工程形态的故障语义与 `mssanitizer --tool=<mode>` 相同，区别在构建和插桩入口：独立 ASC
直接构建可执行程序；标准工程先构建算子包、安装到隔离目录，再由 ACLNN Host 调用。两份日志都应
回到同一个 Kernel 故障分支，不能只写“程序报错”。

## 四、困难题

统一记录至少包含：

```json
{
  "shape": "standalone",
  "mode": "memcheck",
  "command": "mssanitizer --tool=memcheck <binary>",
  "exit_code": 1,
  "signature": "illegal write",
  "source": "src/add_sanitizer.asc:<实际行号>",
  "status": "EXPECTED_DIAGNOSTIC"
}
```

`exit_code` 和行号仅为结构示意，必须填实际值。修复后 baseline 为 `PASS`；msDebug 只有在断点、
backtrace、frame、source 均完成时为 `PASS`，权限不足则整体报告为 `BLOCKED`。

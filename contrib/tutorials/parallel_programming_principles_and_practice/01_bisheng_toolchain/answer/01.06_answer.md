# 参考答案

以下按四类考核逐项给出答案/答案要点与通过标准。报告仍按 Host、Toolkit、Device、Communication 四层组织：先证明 Host 最小程序可运行，再记录 CANN 变量和 bisheng 架构来源；不猜测安装路径，不提供虚构的固定性能数字。

## 1. 客观题（答案与依据）

（1）C（`bisheng`）。依据：`src/hello_world.asc` 是 Ascend C 源文件，本课程中由 `bisheng` 面向 Ascend C/AI Core 编译；`clang++/mpicxx` 生成主机可执行文件，ACL 应用由主机编译器链接 CANN 库，均不用于编译 `.asc` 的算子源。

（2）对。依据：01.03 明确要求从目标环境确认架构参数（`bisheng --help`、产品信息），不能从主机型号猜测；命令模板为 `bisheng src/hello_world.asc --npu-arch=<实际架构> -o build/hello_world`。

## 2. 简单题（答案要点）

- 诊断记录应包含：CANN 相关环境变量（如 `ASCEND_TOOLKIT_HOME`/`ASCEND_HOME_PATH`，以本机实际变量为准）、`npu-smi`/`clang`/`clang++`/`bisheng`/`cmake` 的 `command -v` 位置与版本。
- `hello_host.cpp` 编译前应确认 `clang++ --version` 包含 BiSheng 标识；编译运行：`clang++ -std=c++17 -O2 src/hello_host.cpp -o results/hello_host && ./results/hello_host`；成功时输出 `host toolchain ready` 且退出码为 0。
- 通过标准：命令指向真实文件或可执行文件；输出与源码一致；缺失的工具记为缺失，并按官方指南完成安装。

## 3. 中等题（答案要点）

- 命令模板：`bisheng src/hello_world.asc --npu-arch=<实际架构> -o build/hello_world`；架构参数必须来自目标环境（`bisheng --help` 或产品文档）并记录来源，每个选项说明含义（源文件、目标架构、输出路径）。
- 分层判断依据：Host 层——主机编译器或运行库不可用（如 `clang++` 找不到）；Toolkit 层——CANN 变量缺失或头文件/库路径错误（如 `bisheng` 不在 PATH）；Device 层——`npu-smi` 看不到设备或设备不可用；通信层——MPI/HCCL 相关（本实验仅运行单机 Host 程序，通常不涉及，除非实际执行分布式程序）。
- 通过标准：无 bisheng 环境时如实记录缺失条件，不伪造编译结果，不复制其他硬件的架构值。

## 4. 困难题（综合实践：答案要点与通过标准）

完成四步闭环：环境诊断记录（保存到 `results/toolchain_diagnosis.md`）→ `hello_host` 编译运行 → Ascend C 最小源文件 bisheng 命令（仅目标环境执行）→ 分层判断。

- 提交物：实际命令与环境；阅读或修改的真实文件/函数/参数；字段为“工具、版本/路径、退出码、Host 输出、Ascend C 编译条件”的结果表；正确性判据；基于数据的结论。性能数字不作为固定答案。
- 通过标准：操作链完整；先判断退出码、再核对正确性、最后才谈可比性；若环境缺少 CANN、MPI 或多设备，提交明确的诊断证据，不得把历史 CSV 冒充本机运行结果；结论与实验条件一致。

# 参考答案

参考流程是 baseline -> 假设 -> 单项修改 -> 同参数复测 -> 正确性检查 -> profile 差值 -> 结论。优化无收益也应保留并解释。


## 参考实验操作

实验必须基于 `src/dis_gmres/`。构建并通过 ctest；固定矩阵、restart、tolerance，只在正交化/线程预算/分区中选一个变量；比较前后 residual、iterations 和阶段时间。

建议记录表：

| 配置 | Total | SpMV | Dot/AXPY | HCCL | Residual | Iterations | Speedup |
|---|---|---|---|---|---|---|---|
|  |

分析时先判断退出码、正确性和可比性，再解释性能变化。若环境缺少 CANN、MPI 或多设备，应提交明确的诊断证据，不得把历史 CSV 冒充本机运行结果；参考答案不规定固定耗时。

## 四类考核参考答案

### 1. 客观题

答案：（1）B。`npu_gmres.cpp` 中每次 SpMV 前把本地向量放入全局 Device buffer（memset + D2D 放置），再经 `HcclAllReduce`（`allreduce_device`）形成全局向量，不使用 AllGather。（2）对。章测不把 CGS 结果写死：成功时核对 Device backend、solution error 与 residual；失败时只接受当前源码的明确拒绝信息。当前仓库的 `distributed_gmres_npu` 会返回 `Device CGS multi-dot kernel is not enabled; use --orthogonalization mgs`，且不会回退 CPU。（3）B。矩阵读取/分区与 communicator 初始化位于 repeat 外只做一次；每次 solve 重建 solver 内的 RTC/Device 状态；`--warmup N` 只是额外执行并丢弃 N 次完整 solver invocation，不是 warm cache 稳态指标，也不等于完整进程冷启动。

### 2. 简单题

处理方法：给出命令，如 `DIS_GMRES_REQUIRE_REAL=1 bash scripts/build.sh` 后 `bash scripts/run.sh --npus 1 --matrix U1 --warmup 0 --repeat 3`（或直接运行 `./build/bin/dis_gmres --warmup 0 ...`），并粘贴日志中的 backend、compute backend、device、iteration、residual、total time。说明：矩阵读取/分区与 communicator 初始化位于 repeat 外只做一次；每次 solve 重建 solver 内的 RTC/Device 状态；`--warmup N` 只是额外执行并丢弃 N 次完整 solver invocation，不是 warm cache 稳态指标，也不等于完整进程冷启动。判定条件：命令带 `--warmup 0`、证据字段齐全、warmup 语义解释正确。

### 3. 中等题

处理方法：用与基线相同参数运行 `msprof --application="..." --runtime-api=on --task-time=on` 并 `msprof --export=on`，对导出的 Summary/Timeline CSV 用 Python 标准库（csv/collections）按名称列（Name/Task Name/Op Name/Kernel Name/API）累计耗时（Duration(ns) 除以 1000 转 us），打印 Top 10、总时长与 share%。结合 GMRES 数据流（局部向量 → 全局 Device buffer → HCCL AllReduce → Device SpMV → Dot/Norm/正交化 AXPY → 标量 AllReduce 规约）判断第一瓶颈是计算、通信还是同步。判定条件：引用实际 CSV 列名与数值，Top 10/占比可复核，瓶颈判断与阶段语义一致。

### 4. 困难题

处理方法：先跑 1 rank 基线（`--warmup 0`），再以 2 rank（`--rank-table rank_table_2p.json` 或等价配置）同参数运行，记录每 rank 的 residual/error、总时间与通信占比，计算 speedup 与并行效率并解释扩展性。随后选一个单变量（如 `--partition rows` 与 `nnz`；`cgs` 只有在能力探测成功并通过正确性门槛后才能作为对照），保持矩阵/rank/repeat/tolerance 不变重测，用 CSV/日志对比 total、SpMV、HCCL、迭代数与 residual 形成闭环；结论必须来自实测数据，不能写固定性能数字。总时间与阶段耗时必须使用 rank 0 的 MAX 聚合值（关键路径 wall time，输出标注 `MAX across ranks`）；AllReduce/AllGather 调用次数取最大单-rank 次数（逻辑 collective 调用数），不是跨 rank 总和。每 rank 摘要记录 observed global residual（全局收敛残差，不冒充 local residual）与 local solution relative error（本 rank 分片解误差），不能把 SUM/world_size 的 rank 均值当作端到端 wall time。判定条件：baseline→修改→复测闭环完整、每 rank 证据齐全、结论有实测字段支撑。

# 2.2 参考答案

融合算子减少了中间结果和 Host 下发次数，但 batch=1、单 token decode 的形状很小，FP32↔FP16
转换、算子准备和固定启动成本可能超过融合收益。因此必须固定模型、prompt、steps、解码参数、
Device 和统计范围，并保存完整命令与原始值。

本实验不是“只改变是否融合”的纯单变量实验：Path A 是 FP32 多算子，Path B 是 FP16
FlashAttentionV4 并包含必要 Cast。结论只能归因于整体实现包。可以设计的后续单变量实验包括：

1. 固定 dtype，只改变算子组织；
2. 固定实现包，交换 A/B 运行顺序；
3. 固定实现包，只改变 batch 或序列长度；
4. 用 profiler 分离 Cast、Kernel 和 Host launch 开销。

没有对应真机数据时只能写待验证，不能仅凭算子名称判断性能。

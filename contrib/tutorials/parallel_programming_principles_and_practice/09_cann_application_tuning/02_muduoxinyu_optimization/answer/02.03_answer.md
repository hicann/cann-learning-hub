# 2.3 参考答案

## 一、客观题

1. `functional_pass` 回答两套实现是否功能一致且无 fallback；`performance_valid` 回答样本和统计是否可比；`performance_beneficial` 回答 B 在本次 workload 下是否比 A 快。
2. 不是。还同时改变了 dtype：Path A=FP32 多算子，Path B=FP16 FlashAttentionV4 + Cast。
3. 可以。应写“功能通过、数据有效、性能不受益”。
4. 防止覆盖旧日志、混入旧样本或把不同提交的证据合并。
5. 错。4.28% 只是旧环境历史记录。

## 二、简单题

预检至少记录：精确 baseline HEAD、工作树/候选补丁状态、模型和 tokenizer 路径/大小/SHA256、
Device、CANN 路径、输出目录尚不存在。课程不记录完整环境变量，也不自动清理工作树。

## 三、中等题

先检查 smoke 的 Path A/Path B marker、fallback=0、FlashAttention 调用次数和 token exact；再检查
performance 的 sample 1~4、退出码、三轮 mean/CV 和 token exact。`run_manifest.json` 的顺序应为
`smoke_a → smoke_b → perf_b → perf_a`，并与原始日志属于同一输出目录。

## 四、困难题

先检查 `functional_pass`，再检查 `performance_valid`，最后依据 B/A mean 判断
`performance_beneficial`。若 B 的 mean 更低，应如实写“功能通过、性能不受益”。

可证伪的后续实验只能改变一个变量，例如固定 dtype 后比较算子组织，或保持实现包不变只交换运行
顺序。没有 profiler 证据时，不能把差异单独归因于 Cast、布局或 launch 开销。

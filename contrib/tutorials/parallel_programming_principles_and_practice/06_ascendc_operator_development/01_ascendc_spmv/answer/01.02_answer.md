# 参考答案

需要构建证据（CANN/ACL/Ascend C 依赖与 Device target）、调用证据（ACL Runtime 或真实 Kernel launch）和运行证据（设备日志/profiler）。当前 CMake 默认 `SPMV_REAL_ASCENDC=ON`：查找 `acl/acl.h`、`ascendcl`、`acl_rtc`，编译 `ascendc_spmv.cpp`（`AscendCSpmvBackend`）并链接 Device 库；FP32 正式路径输出 `Actual Backend=Ascend C RTC`、CSV 字段 `actual_backend=ascend_c`。FP16/BF16/persistent 仍是 Host 原型，不能仅凭类名或字段名证明 Device 执行。


## 参考实验操作

实验必须基于 `src/ascend_spmv/`。构建运行 benchmark，沿 `ISpmvBackend` 追踪各实现；比较精度、partition、cold/warm 和误差；FP32 正式路径已有 Device API（`AscendCSpmvBackend`），FP16/BF16/persistent 无 Device 调用时只报告主机原型证据。

|  |

分析时先判断退出码、正确性和可比性，再解释性能变化。若环境缺少 CANN、MPI 或多设备，应提交明确的诊断证据，不得把历史 CSV 冒充本机运行结果；参考答案不规定固定耗时。

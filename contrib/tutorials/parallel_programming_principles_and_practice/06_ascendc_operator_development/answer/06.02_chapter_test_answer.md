## 第二部分 简单题（答案要点）

- 子路径 A：SpMV kernel 在 **SIMD/Vector Core** 上执行；当前**没有**可声称通过的 SpMV SIMT 真机路径。
- 子路径 B：RoPE 的 SIMD 路径通过 **Ascend C RTC（运行时编译）** 打通并完成真机执行；SIMT 模板面向 **Ascend 950**，当前 A3 不支持。
- 边界表述：SIMD 已通过；**SpMV SIMT 未验证、不得 PASS**；**RoPE SIMT 为 Ascend 950 模板，A3 状态为 `DEFERRED_UNSUPPORTED_TARGET`**。

## 第三部分 中等题（答案要点）

- 声称一（SpMV SIMT 已在 A3 通过）需要核实的证据清单：
  1. 构建证据：是否真实编译了 SIMT kernel，编译目标与命令是什么；
  2. 调用证据：程序是否实际提交并执行该 kernel，日志能否定位执行位置；
  3. 正确性证据：NPU 输出与 CPU/NumPy 参考是否一致；
  4. 运行记录：运行环境是否为 A3，是否与声称一致。
   判定：当前**未验证、不得 PASS**；本实验中 `DEFERRED_UNSUPPORTED_TARGET` 仅用于 RoPE SIMT，不用于替代所有「未验证」结论。
- 声称二（RoPE 只有 SIMD 一种实现）遗漏了 **SIMT 模板路径**（Ascend 950 only）。该模板当前仅在模板层面存在，A3 未验证，不能作为已通过路径引用。

## 第四部分 困难题（答案要点与通过标准）

- 方案一：报告需包含编译命令与输出、执行位置证据（kernel 名/核类型/日志）、NPU 输出与 NumPy 参考一致；结论只描述执行时间数据，不做性能收益断言。
- 方案二：报告需包含 RoPE SIMD/RTC 的运行与数值正确性对比；SIMT 部分说明仅为模板、面向 Ascend 950、A3 状态为 `DEFERRED_UNSUPPORTED_TARGET`。
- 通过标准：证据链完整（构建 + 调用 + 正确性）；不把 SIMT 写成真机已通过。

# 并行软硬件架构（第二章）

## 课程简介

本章是全课程的硬件基础。理论部分讲授现代处理器的执行机制（流水线、超标量、乱序执行、分支预测）、存储子系统（存储层次、Cache 与 TLB、3C 缺失模型、MESI 协议）、并行硬件架构（Flynn 分类、SIMD、UMA/NUMA）与并行软件运行机制。

配套实验只有一个，但它是本章的**综合实训**：用三个递进的对照实验把"存储系统是性能的核心关键"这句话变成可测量的数字。遍历顺序实验呈现"仅交换循环次序即导致执行时间相差一个数量级"的现象；访存步长实验由单次读取代价的拐点测出有效搬运粒度（缓存行大小）；指针追逐实验通过随机化的指针追逐测出各级缓存的容量与延迟。三者所得参数可与硬件参数值逐项核对，并反过来定量解释第一个实验中的每一个比值。扩展任务以分块矩阵转置收尾，把空间局部性从"观察到的现象"变成"可主动使用的优化手段"。

## 适合人群与前置要求

面向具备 C 语言基础、了解数组与指针的学习者。无需并行编程经验，本章不涉及多线程与 NPU。

建议在阅读实验前先了解存储层次结构与局部性原理的基本概念。本章测得的缓存行大小与各级缓存容量，将在第三章（NEON 分块与打包）、第四章（伪共享）、第五章（伪共享与数组段归约）中反复被引用。

## 学习目标

- 掌握存储层次结构与局部性原理，理解"越靠近处理器容量越小、速度越快"的成因；
- 能够用 3C 缓存缺失模型解释缓存缺失的来源；
- 能够实测本机的缓存行大小以及各级缓存的容量与访问延迟；
- 能够用实测得到的硬件参数，定量解释同一计算量下不同遍历顺序的时间差异；
- 能够运用分块把空间局部性转化为主动使用的优化手段。

## 实验环境说明

- 本实验仅依赖标准 C 库与 GCC，不依赖 CANN、NEON 或多线程库。
- 所有源码通过 `%%writefile` 内嵌在 Notebook 中，请自上而下依次执行各单元格（Shift+Enter）。
- 实测数值随处理器型号、内存频率与系统负载变化，学习时应关注**拐点位置与比值关系**，而非绝对时间。
- 若指针追逐实验测出的层级数与本机 `lscpu` 报告的缓存层级不一致，请先确认运行环境是真实硬件而非虚拟化 / 模拟环境。
- 在线体验链接由仓库维护人员配置，当前记为 `-`。

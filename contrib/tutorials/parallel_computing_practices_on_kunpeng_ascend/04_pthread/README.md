# Pthreads 多线程编程（第四章）

## 课程简介

本章进入**线程级并行**：多个线程在同一地址空间内并发执行，性能来自多个 CPU 核心，代价是必须自己管理同步与数据一致性。理论部分讲授 Fork-Join 模型与 Pthreads 核心 API、数据竞争与临界区、互斥量与死锁（Coffman 条件）、信号量、条件变量 / 屏障 / 读写锁等高级同步原语，以及伪共享与 C11 原子操作。

配套实验共 10 个，按"能跑 → 会错 → 会修 → 会选"的顺序组织：从 Hello World 观察 Fork-Join 与执行的非确定性开始，用 GEMV 练习数据分解与线程传参，用 π 估算复现数据竞争并比较锁粒度，用哲学家就餐理解死锁、活锁与资源分级，用消息传递与生产者-消费者对比四种同步策略的递进，再通过向量归一化（屏障）、并发链表（读多写少的锁策略）、伪共享（正确但很慢的程序）建立选型判断，最后以线程池综合实训收尾——把互斥锁、条件变量、生产者-消费者等单项技术组装为一个可复用的线程池，并用它完成 Mandelbrot 集渲染。

线程池实训中安排了两组受控对照与两次故障注入：无池与动态队列的差异回答"为什么需要池"，粗粒度与细粒度的差异回答"为什么需要队列"；条件等待误用 `if` 导致的崩溃与关闭语义写反导致的静默任务丢失，则演示并发缺陷的两种典型面貌。

## 适合人群与前置要求

面向具备 C 语言基础、了解函数指针与结构体的学习者。建议先完成第二章，本章的伪共享实验直接使用第二章测得的缓存行大小。

本章不涉及 SIMD 与 NPU；第五章将用 OpenMP 重做其中若干问题，对照两种抽象层次的差异。

## 学习目标

- 能够使用 Pthreads 核心 API 创建、传参与回收线程，并完成任务分解；
- 能够判定一段代码是否存在数据竞争，并复现、解释竞争导致的结果不确定性；
- 能够用互斥量正确保护共享数据，依据 Coffman 条件分析并破除死锁；
- 能够用信号量实现同步与资源计数，实现有界缓冲的生产者-消费者模型；
- 掌握条件变量"循环判定 + 等待"的标准范式，理解屏障的三种实现与读写锁的适用场景；
- 能够识别并消除伪共享，在原子操作与互斥量之间做出合理选型；
- 能够设计并实现一个可复用的线程池，用不均衡因子刻画负载分布、用粒度扫描建立任务粒度的权衡模型。

## 实验环境说明

- 运行前请用 `nproc` 确认可用核心数；核心数过少时请相应下调实验中的线程数配置，否则观察到的加速比不具备参考意义。
- 所有源码通过 `%%writefile` 内嵌在 Notebook 中，请自上而下依次执行各单元格（Shift+Enter）。
- **多线程程序每次运行的线程交错顺序可能不同**：Hello World 的输出顺序、π 估算的错误数值都不会每次一样，这正是本章要观察的现象，不是实验失败。
- 涉及故障注入的单元格（如条件等待误用 `if`、关闭语义写反）会**故意产生错误结果或崩溃**，请按 Notebook 中的说明观察后再执行修复版本。
- 参考耗时会随核心数、编译器版本与系统负载变化，学习时应关注版本之间的相对变化及其成因。
- 遇到 🔧 **动手练习** 与 🤔 **思考题** 时，建议先独立完成，再阅读后续内容。
- 在线体验链接由仓库维护人员配置，当前记为 `-`。

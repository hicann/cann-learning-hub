# 实验 1.2 昇腾香橙派开发板系统制作烧录与基础运行实验 —— 拓展题参考答案

## 一、选择题

### 1. Orange Pi AI Pro 开发板的拨码开关 BOOT1=右、BOOT2=右 时，开发板从哪种介质启动？

**答案：B. TF 卡**

**解析：** 根据拨码开关与启动设备对应关系表，BOOT1=右、BOOT2=右 对应 TF 卡启动。这是本实验的默认配置。完整对应关系如下：

| BOOT1 | BOOT2 | 启动设备 |
|---|---|---|
| 左 | 左 | 未使用 |
| 右 | 左 | SATA SSD 和 NVMe SSD |
| 左 | 右 | eMMC |
| **右** | **右** | **TF 卡** |

---

### 2. 烧录完成后 Windows 弹出 "是否格式化磁盘" 提示，正确的操作是？

**答案：B. 点击"取消"**

**解析：** 烧录完成后 TF 卡已被写入 Linux 分区（ext4 等格式），Windows 无法识别该文件系统，因此会弹出格式化提示。这是正常现象，点击"取消"即可。如果点击"格式化磁盘"，会将已烧录的 Linux 镜像破坏，导致开发板无法启动。

---

### 3. 切换拨码开关后，以下哪种操作能让新配置生效？

**答案：C. 重新拔插电源上下电**

**解析：** 拨码开关的启动设备选择是在上电时由硬件读取的。切换拨码开关后，必须重新拔插电源（断开再接通 Type-C 电源）才能让新的启动设备选项生效。按复位按键（Reset）只会重启系统，不会重新读取拨码开关状态，因此无效。执行 `reboot` 命令同样是软重启，也无法让拨码开关新配置生效。

---

### 4. Orange Pi AI Pro 默认的 SSH 登录密码是？

**答案：D. Mind@123**

**解析：** Orange Pi AI Pro 官方 Linux 镜像的默认账号和密码为：
- root 用户：密码 `Mind@123`
- HwHiAiUser 用户：密码 `Mind@123`

只要使用的是 Orange Pi 官方提供的 Linux 镜像，密码就是 Mind@123。如果输入密码提示错误，不要怀疑密码不对，而应排查其他原因（如网络连通性、IP 地址等）。

---

### 5. 关于烧录 eMMC 和 SSD，以下说法正确的是？

**答案：B. 需要借助 TF 卡系统中转烧录**

**解析：** 开发板没有提供直接从电脑烧录 eMMC 和 SSD 的通道（不像 TF 卡可以通过读卡器直接在电脑上写入）。烧录 eMMC 和 SSD 的正确流程是：
1. 先将 Linux 镜像烧录到 TF 卡
2. 用 TF 卡启动开发板进入 Linux 系统
3. 在开发板上运行预装的 balenaEtcher，将镜像写入 eMMC（/dev/mmcblk0）或 SSD（/dev/nvme0n1）
4. 调整拨码开关，重新上电从新介质启动

## 二、判断题

### 6. balenaEtcher 可以直接烧录 `.img.xz` 压缩格式的镜像，无需手动解压。

**答案：正确（√）**

**解析：** balenaEtcher 支持直接识别 `.img.xz` 压缩格式的镜像文件，烧录时会自动解压。而使用 Win32Diskimager 则需要先手动解压得到 `.img` 文件才能烧录。

---

### 7. 开发板上有两个绿色 LED 灯，靠近关机按键的绿灯由软件控制其亮灭。

**答案：错误（×）**

**解析：** 靠近关机按键的绿灯是**电源指示灯**，由**硬件控制**其亮灭，软件无法控制。只要开发板接入了 Type-C 电源并上电，此绿灯就会点亮。另一个绿灯（MIPI LCD 与 CAMERA0 之间）才是由 GPIO4_19 软件控制的。

---

### 8. 通过修改 `/etc/network/interfaces` 配置文件来连接 WIFI 是推荐的做法。

**答案：错误（×）**

**解析：** 在 Orange Pi AI Pro 的 Linux 系统上，通过修改 `/etc/network/interfaces` 配置文件来连接 WIFI 会出现问题。正确的做法是使用 `nmcli` 命令或 `nmtui` 图形化界面来连接 WIFI。例如：
```bash
sudo nmcli dev wifi connect wifi_name password wifi_passwd
```

---

### 9. 调试串口的波特率必须设置为 115200。

**答案：正确（√）**

**解析：** 开发板默认使用 uart0 作为调试串口，波特率固定为 115200。在串口终端软件（如 MobaXterm、putty）中必须将 Speed(baud) 设置为 115200，流控设置为 None，才能正常接收串口输出信息。

---

### 10. Orange Pi AI Pro 搭载的昇腾 AI 处理器可提供 8 TOPS INT8 的计算能力。

**答案：正确（√）**

**解析：** Orange Pi AI Pro 搭载昇腾 AI 处理器（Ascend 310B4），可提供 8 TOPS INT8（整数精度）和 4 TFLOPS FP16（半精度）的计算能力。这使得开发板能够胜任图像分类、目标检测等边缘 AI 推理任务。

## 三、简答题

### 11. 为什么烧录 eMMC 和 SSD 不能像 TF 卡一样直接在电脑上完成，而需要先制作 TF 卡启动系统？

**答案：**

这是因为 eMMC 和 SSD 是直接焊接或插接在开发板上的存储芯片，电脑无法像访问 TF 卡（通过读卡器映射为可移动磁盘）那样直接访问它们的底层扇区。具体原因如下：

1. **接口差异**：TF 卡通过读卡器连接电脑后，会被识别为标准的 USB 大容量存储设备，电脑可以直接对其扇区进行读写。而 eMMC 和 SSD 连接在开发板的内部总线上（eMMC 在 MMC 总线上，SSD 在 PCIe 总线上），电脑无法直接访问。

2. **没有直烧通道**：开发板没有提供从电脑直接烧录 eMMC / SSD 的硬件通道或工具。

3. **中转方案**：因此需要先用 TF 卡启动开发板进入 Linux 系统，在 Linux 系统中 eMMC 和 SSD 会被识别为块设备（`/dev/mmcblk0`、`/dev/nvme0n1`），然后使用开发板上预装的 balenaEtcher 将镜像写入这些块设备。

---

### 12. 切换拨码开关后为什么必须重新上下电才能生效，而按复位键无效？

**答案：**

1. **拨码开关的读取时机**：拨码开关的启动设备选择状态是在**上电瞬间**由硬件电路（Boot ROM）读取的。Boot ROM 在上电时根据拨码开关的电平状态决定从哪个介质加载引导程序。

2. **复位键的作用**：复位键（Reset）只是对 SoC 芯片进行硬件复位（Reset），相当于 CPU 重新开始执行，但**不会重新上电**，电源一直保持接通状态。此时 Boot ROM 不会重新读取拨码开关状态，而是按照上电时已经锁存的配置继续启动。

3. **重新上下电的作用**：重新拔插电源意味着完全断电再上电，此时 Boot ROM 会重新读取拨码开关的最新状态，从而按照新的配置选择启动设备。

因此，切换拨码开关后必须重新拔插电源上下电，仅按复位键无法让新配置生效。

---

### 13. 如何通过板载两个 LED 灯的状态初步判断开发板的上电与内核启动情况？

**答案：**

开发板上有两个绿色 LED 灯，可以通过它们的状态进行初步判断：

| LED 灯 | 控制方式 | 状态含义 |
|---|---|---|
| 靠近关机按键的绿灯 | 硬件控制（电源指示灯）| **亮** = 已接入 Type-C 电源并上电；**灭** = 未上电或电源故障 |
| MIPI LCD 与 CAMERA0 之间的绿灯 | GPIO4_19 软件控制 | **亮** = Linux 内核已启动并加载 DTS 配置；**灭** = 内核未启动或启动失败 |

**判断方法：**
- **两个灯都不亮**：开发板未上电，检查电源连接。
- **只有电源灯亮，GPIO 灯不亮**：已上电但 Linux 内核未启动，可能拨码开关设置错误、TF 卡未插入或镜像烧录失败。
- **两个灯都亮**：上电正常且 Linux 内核已启动，系统应该可以正常使用。

### 14. 在无法连接 HDMI 显示器的场合，可以通过哪几种方式登录开发板的 Linux 系统？

**答案：**

在无法连接 HDMI 显示器的场合，可以通过以下方式登录开发板的 Linux 系统：

1. **SSH 远程登录**：
   - 将开发板通过网线连接到与电脑相同的局域网
   - 通过路由器管理后台查找开发板 IP 地址（设备名通常为 `orangepiaipro`）
   - 在电脑终端执行 `ssh root@<开发板IP>` 或 `ssh HwHiAiUser@<开发板IP>`
   - 输入默认密码 `Mind@123`

2. **调试串口登录**：
   - **Micro USB 方式（推荐）**：用 Micro USB 数据线连接开发板与电脑，使用 MobaXterm（Windows）或 putty（Ubuntu）设置串口波特率 115200
   - **40 pin 方式**：用 3.3V USB 转 TTL 模块连接开发板 40 pin 接口的 uart0 引脚（8 号 TX、10 号 RX），设置波特率 115200

3. **如果已连接 WIFI 天线**（但首次配置仍需上述方式之一登录）：
   - 首次需要通过 SSH 或串口登录后，使用 `nmcli` 命令连接 WIFI
   - 连接成功后即可通过 WIFI 网络进行 SSH 远程登录

### 15. 简述 Orange Pi AI Pro 开发板三种启动介质（TF 卡、eMMC、SSD）的烧录流程差异。

**答案：**

| 比较项 | TF 卡 | eMMC | NVMe SSD |
|---|---|---|---|
| **是否可直接在电脑烧录** | 是（通过读卡器）| 否 | 否 |
| **烧录工具** | Win32Diskimager / balenaEtcher | balenaEtcher（开发板上）| balenaEtcher（开发板上）|
| **是否需要 TF 卡中转** | 否 | 是 | 是 |
| **设备节点** | 电脑上的可移动磁盘 | /dev/mmcblk0 | /dev/nvme0n1 |
| **拨码开关（BOOT1/BOOT2）**| 右 / 右 | 左 / 右 | 右 / 左 |
| **镜像格式** | .img 或 .img.xz | .img.xz（自动解压）| .img.xz（自动解压）|

**流程差异总结：**

- **TF 卡**：最简单，将 TF 卡插入读卡器连接电脑，直接使用 Win32Diskimager 或 balenaEtcher 烧录镜像即可。
- **eMMC**：需要先将镜像烧录到 TF 卡，用 TF 卡启动开发板进入 Linux 系统，确认 eMMC 已识别（`fdisk -l` 看到 `/dev/mmcblk0`），将镜像上传到开发板，使用 balenaEtcher 烧录到 `/dev/mmcblk0`，最后将拨码开关拨到 eMMC 启动位置（左-右）。
- **NVMe SSD**：流程与 eMMC 类似，但设备节点为 `/dev/nvme0n1`，在 balenaEtcher 中需要点击 "Show 1 hidden" 展开隐藏设备，拨码开关拨到 SSD 启动位置（右-左）。注意目前仅三星品牌 NVMe SSD 能稳定运行。

# 9.5 小测验答案

**1. 写出切 S2 后各核的部分统计量与 merge 归并公式。**

各核 i 输出：m_i（段内行最大值）、l_i（段内 exp(x−m_i) 之和）、acc_i（段内 exp(x−m_i)·v 之和）。
归并：
```
M   = max_i(m_i)
L   = Σ_i l_i · exp(m_i − M)
ACC = Σ_i acc_i · exp(m_i − M)
attn = ACC / L
```

**2. 缩放因子 exp(m_i − M) 为什么不可省略？去掉会怎样？**

各核的局部统计量是以各自的 m_i 为基准算的指数；全局基准是 M = max(m_i)。基准不同，指数和不可直接相加——必须乘 exp(m_i − M) 把各段从「以 m_i 为基准」重新对齐到「以 M 为基准」。去掉后每核的分母/分子用不同基准的指数相加，结果完全错误（数值实验里与参考实现的误差会达到数量级级别）。

**3. merge kernel 为什么选临时 buffer 形态而不是原子规约？**

临时 buffer：各核把 (m, l, acc) 写到 GM 的 (行数×核数) buffer，merge kernel 作为纯 Vector 任务读入归并，与主循环解耦、可流水。原子规约虽然实现简单，但原子 max/加法在多核间竞争严重、性能差，且 exp 缩放的归并逻辑不是简单加法，原子操作表达不了。

**4. 切 S2 的段数是不是越多越好？成本账怎么算？**

不是。并行度上限是核数，段数 = 核数后收益封顶；而 merge 成本随段数线性上涨：① 临时 buffer 读写（核数×行数×(1+1+d) 个元素，GM 两跳）；② merge kernel 归并计算（行数×核数，纯 Vector）；③ 核间同步（所有分段核完成才能启动 merge）。

**（附加）为什么说在线 softmax 的本质是「局部统计量 + 可交换的归并」？**

在线 softmax 在任何作用域（块间 update、核间 merge、甚至多卡 Ring Attention）都只维护 (m, l, acc) 三个局部统计量，归并规则（max 基准对齐 + 加法）与顺序无关、可交换——因此可以任意切分、任意顺序合并，这正是 FA 能沿任何轴并行化的数学根基。

# 8.6 小测验答案

**1. Scalar 指令「不干活」，为什么会拖慢 Cube 和 Vector？**

三个机制：① 量大——循环控制、地址计算、Set/WaitFlag 都是标量指令，插在 Cube/Vector 指令流里发射，占用发射周期；② 依赖长——地址算完才能发对应的 Load，Scalar 延迟直接传导为 Vector/Cube 的空等；③ 分支抖——分支两侧代码都要发射，且跳转让流水重新充满。

**2. addr = base + i * stride 在循环内怎样改写？写出改写前后的指令数对比。**

改写为增量累加：循环外算初值 addr = base，循环内只做 addr += stride。
改写前：每轮 1 次乘法 + 1 次加法（2 条，乘法更贵且依赖 i）；改写后：每轮 1 次加法（1 条，且与 i 无依赖链）。n 轮循环从 2n 条降到 n 条，且地址依赖链更短。

**3. 三种分支消除手段各适用什么场景？掩码方案的正确性前提是什么？**

① 掩码代替分支：适用于「无效位置填 0 无害」的计算（累加、softmax 分母等）；
② 查表代替多路分支：适用于分支结果是离散常量、分支数固定（如参数选择）；
③ 模板特化（编译期把 isTail 做成模板参数，配合 TilingKey）：适用于分支条件在运行期不变（尾块与否在 Tiling 后就确定）的场景。
掩码方案的正确性前提：被乘 0 的值不会污染结果——累加、max、softmax 的数值语义满足；若 0 会破坏语义（如做除数）则不能直接掩码。

**4. 为什么说「标量上提」是收益最大且零风险的优化？**

收益最大：上提把整个计算从 kernel 侧完全删除（循环次数 × 每轮指令数全部消失），而增量化、掩码化只是把每轮开销减半或减到 1/4；零风险：Host/Tiling 侧是普通 CPU 代码，有调试器、可单步、语义与 kernel 完全一致，不引入任何数值风险。前提判断也简单——凡是不依赖运行时数据的计算都能上提。

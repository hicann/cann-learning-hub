# 8.5 小测验答案

**1. 画出 ND 与 DN 两条通路的数据流（从 GM 到 L0），标出 Vector 的参与点。**

```
ND: GM --MTE2--> UB --Vector: TransData(ND2NZ)--> UB --MTE3--> L1 --MTE1--> L0(Cube, NZ 分形)
                        ↑ Vector 参与点（转排布，无算法价值）

DN: GM --MTE1(ND 模式)--> L0(Cube 直接以 ND 取数)
                        ↑ Vector 全程不参与
```

**2. 为什么带 attention mask 的场景 DN 不划算？**

mask 必须在 mm1 之前把掩码值叠加到 QKᵀ 相关输入上，这只能在 Vector 完成。既然 Vector 反正要读这块数据、UB 里反正有中转，就顺手把 TransData 做了；DN 省掉的就是这次中转，此时中转已经不可避免，DN 的收益消失，反而 DN 通路额外的对齐约束成了纯负担。所以 mask/pse/drop 任一存在，走 ND 更好。

**3. VF 建模的公式是什么？为什么 VF 可以静态建模而 CPU 代码很难？**

T_VF = Σ(每条指令的发射延迟) + Σ(相邻依赖指令间的等待)。
建模步骤：vLoop 展开 → 每轮数指令条数（优化后）→ 查表累加延迟 → 有写后读的位置加等待周期。
VF 可以静态建模，因为它是顺序执行、无 Cache（延迟确定）、无分支惩罚（无预测错误开销）——指令序列和每条延迟在写代码时就是确定的。CPU 代码受 Cache 命中率、乱序窗口、分支预测影响，运行前无法准确估。

**4. 建模发现某 VF 函数中 Load/Store 占了 70% 周期，下一步优化方向是什么？**

瓶颈在搬运不在计算，方向：
① 合并相邻的 Load/Store（同一块数据一次搬运进寄存器后用不同视角消费）；
② 检查是否有 bank 冲突（第7章 7.3 的判定方法），用 pingpong / 多 bank group 分布消除；
③ 减少搬运总量：如广播装载替代逐行 Duplicate、数据复用；
④ 编排上用寄存器双缓冲让 Load 与计算重叠，而不是串行等待。

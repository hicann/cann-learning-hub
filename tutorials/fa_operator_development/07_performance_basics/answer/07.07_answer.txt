07.07 章节测验 —— 参考答案

1. （建模）
   - I = BaseM·BaseN/((BaseM+BaseN)·D_size) = 128·128/((128+128)·2) = 16384/512 = 32 MAC/B。
   - 拐点 I* = 160 MAC/B > 32，处于带宽受限区间——优化方向是加大块 / 减小访存（量化），优化计算指令无收益。
   - 加大到 256×256：I = 256²/(512·2) = 64，仍 < 160，仍带宽受限（性能随 I 线性涨到 2 倍）；继续加大逼近 160 才触顶，之后进入计算平台、只浪费 UB。

2. （混合带宽）
   - B_mix = B_HBM·B_L2/(∂·B_L2 + (1−∂)·B_HBM)；∂ 是 HBM 访存量占比（L2 未命中率）。
   - ∂=1：B_mix = B_HBM；∂=0.5、B_L2 = 5·B_HBM：B_mix = 5·B_HBM²/(0.5·5·B_HBM + 0.5·B_HBM) = 5/3·B_HBM ≈ 1.67×——命中率抬高屋顶，性能上限乘 1.67。

3. （bank 冲突）
   - 0x0000 与 0x0200：block 起始 0 与 512，对 256 取模余数都是 0 → 读读冲突成立；差 512 可被 512 整除 → 读写冲突也成立。
   - 改到 0x0040：block 起始 0 与 64，mod 256 分别为 0 与 64 → 不相等，永不冲突（错开了 bank）。
   - 三板斧：① 单条 VEC 指令操作 ≤ 256B；② 读写 pingpong（输入输出分放乒乓缓冲）；③ 读/写的 8 个 block 分布到 8 个不同 bank group。

4. （均衡性）
   - 按有效块计数：mask 下每行的真实 S2 块数不同，按形状计数名义均衡、实际失衡；GetCutBlockNums 把完全遮盖的块减掉后才是真实工作量。
   - `sInnerBlockNums - dif > dif`（当前行块数超剩余缺口两倍才切核）避免把一行劈到两个核——跨核 softmax 归约复杂；代价是负载离散抖动（行粒度），行块越多（细粒度 BN1S1）抖动越小。
   - 按行分配的代价：最差核超出期望（如模拟中 1.47 倍），行粒度是均衡度的下界。

5. （CV 流水）
   - preload 用两个 Cube 拍（task i 的 C2 和 task i+1 的 C1）掩盖一个长 V1，同时 MTE 提前一个 task 搬数掩盖 C1 的输入等待——V1=8 > C1+C2=6，Cube 队列始终有活。
   - 缩短 V1 的两条路径：① VF 化（Softmax VF 函数族，一条指令 64 个 FP32，寄存器内连续计算）；② 配平 CV（AIC:AIV=1:2 下用 nRatio 等参数调整两侧任务比例，同时干完）。

6. （核内流水）
   - RegBase 多了 RegisterFile 一级：GM → UB → RF → UB → GM，计算在寄存器间流转，省掉回 UB 的读写。
   - 一条 VF 指令处理 64 个 FP32（寄存器 256B ÷ 4B）。
   - vLoop：repeatTimes = ceil(size/64)，每次处理一个寄存器宽的数据；尾块用 MaskReg 标识有效位（ZEROING 模式），不为尾块单写循环。
   - VF 定位三步法：先排除 VF 外围（打印 UB 验证错误在内）→ 从 vLoop 起手推公式逐条验证 → 寄存器数据 ST 回 UB 打印对比。

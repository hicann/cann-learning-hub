《FlashAttention 算子开发课程》第 2 章 2.9 节测验答案
====================================================

1. KV Cache 字节数 = 2（K 和 V 两个矩阵）× 层数 × KV 头数 × d_head × 序列长度 × 精度。

2. GQA 省的是 KV Cache 的显存与带宽：KV 头数从 h 减到 g，缓存缩为 g/h（如 8/32=25%，
   省 75%），质量几乎无损。
   同时它改变了 FA 算子的负载形状：同组各头的 Q 拼成大矩阵一次算完，
   单头负载从 (n, d) 变成 (g·n, d)——Q 侧行数翻 g 倍，正是推理算子最典型的
   工作负载，也是接口里 num_heads / num_kv_heads 两个参数的由来。

3. 因为 RoPE 是旋转运算，与"先低秩压缩、再上投影展开"不可交换——旋转后的 K
   无法从压缩向量 c_t 中无损恢复。MLA 只能把 K 拆成两段：位置无关的 d_c 维走
   压缩通路，位置相关的 RoPE 维单独投影、单独缓存。
   d_c=512、RoPE 通道 64 时，每层每 token 缓存 512 + 64 = 576 个数
   （对比 MHA 的 2×128×128 = 32768，压缩 57 倍）。

4. 因为矩阵乘满足结合律：(q·W)·c = q·(W·c)，两种括号方式结果恒等（本节实验
   allclose 验证为 True）。吸收后不再需要为每个缓存 token 展开每头的 k：
   推理时把上投影 W_UK 预先吸收进 Q，点积直接打在 512 维的压缩向量 c 上，
   KV Cache 里永远只存 c。

5. 共同思想：跳过"不需要算"的注意力位置，避免无谓的计算与搬运。
   本质区别：因果掩码跳过的是由位置规则决定的块（下三角结构，静态、可预测、
   对每个查询行都相同的列模式）；SFA 跳过的是由模型学出来的关键 token
   （Lightning Indexer 打分 TopK，动态、内容相关、每个查询行各不相同）。
   且 SFA 对选中的 token 计算仍是精确的。

6. 核心难题：离散访存——TopK 选中的 token 在 KV Cache 里位置七零八落，
   单次搬运小、指令下发频繁，指令下发的耗时甚至可能超过数据搬运本身。
   对策举例：
   ① 利用 Cube:Vector = 1:2 的核配比让 Vector 核发射访存指令，与计算并行；
   ② 对离散数据做两两聚合（如 srcGap 参数），把零散搬运合并；
   ③ Indexer 的 ReLU 用 Cube 核 FixP 组件随路计算、TopK 做成融合算子，
     不占独立 kernel。

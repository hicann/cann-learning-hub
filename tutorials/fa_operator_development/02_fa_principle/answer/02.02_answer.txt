《FlashAttention 算子开发课程》第 2 章 2.2 节测验答案
====================================================

1. 痛点一：串行——第 t 步依赖第 t−1 步的隐状态，无法并行训练，GPU 大量核心闲置；
   痛点二：长程依赖衰减——信息要经 t 步接力传递，距离远了就"传丢了"。
   Transformer 用自注意力分别解决：任意两个 token 直接建立一条连接（信息路径 O(1)），
   且整个序列的所有位置可以并行计算。

2. O(n²·d)（单层、单头）。换来两个好处：
   ① 全序列并行——所有位置的打分同时算；
   ② 全局视野——任意两 token 一步直达，长程信息不再衰减。

3. 单块参数中 FFN 约占 2/3（Llama-3-8B 约 72%）；
   但序列长度 n 增大时，计算量占比增长最快的是 Attention 核心（QKᵀ 与 PV 两个 GEMM，
   随 n 平方增长；投影与 FFN 都只随 n 线性增长）。

4. 错。n=128k 时 Attention 核心占比超过 70%，成为第一瓶颈，应该优先优化的是 Attention
   ——这正是 FlashAttention 存在的理由。FFN 虽然参数多，但计算量随 n 线性增长，
   长上下文时被平方增长的 Attention 反超。

5. Prefill：一次处理整段 prompt，Q 是 n×d 的大矩阵，大矩阵 GEMM，算力瓶颈；
   Decode：逐 token 生成，每步只有 1 行 Q，但要读全部历史 KV Cache，带宽瓶颈。
   对应昇腾 FusedInferAttentionScore 算子的 PromptFlashAttention / IncreFlashAttention
   两条分支。

6. 因为 Attention（打分-归一化-加权求和）对输入顺序是排列不变的：把 token 打乱后按同样
   顺序打乱 K/V，输出只是跟着重排，数值不变。也就是说结构本身"看不见"位置，
   必须由位置编码额外注入顺序信息。

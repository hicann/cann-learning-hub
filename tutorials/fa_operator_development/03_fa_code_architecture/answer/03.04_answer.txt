《FlashAttention 算子开发课程》第 3 章 3.4 节测验答案
====================================================

1. 两大矛盾约束：
   - Tiling 要「厚」：把尽可能多的计算从 Kernel 侧 Scalar 上提到
     Host 侧，Kernel 拿表执行即可（Scalar 资源宝贵）；
   - Tiling 又要「轻」：TilingData 随任务下发到每个核，体积大
     带来更大的图开销和同地址访问开销；且 Tiling 每次调用都要执行，
     自身太慢会拖累端到端。所以负载均衡等算法也不宜过复杂。

2. TilingKey 治「ICache Miss」。融合算子输入组合众多，全部场景的
   代码混编在一个 Kernel 里，代码段膨胀，而指令缓存容量有限
   （AIC 32KB / AIV 16KB），运行时大量指令缓存未命中，被迫去慢存储
   取指令。TilingKey 在编译期把不同场景的代码隔离，每个 Kernel
   只包含自己场景的代码段。

3. GRAPH_PARAM_INVALID 表示「本模板不支持当前场景」，框架会继续
   按注册优先级尝试下一个模板；GRAPH_FAILED 表示流程性失败，
   框架直接终止整个 Tiling 流程并报错，不再尝试后续模板。

4. 三个理由：
   - Scalar 单元算力极弱，每个核都重复算一遍相同的切分逻辑，
     纯属浪费；
   - 多核各算各的容易引入不一致的风险，Host 统一算好、
     Kernel 只读表，正确性更容易保证；
   - 算好后的 TilingData 是紧凑定长的，随任务一次下发，
     比每核现场计算更快也更省资源。

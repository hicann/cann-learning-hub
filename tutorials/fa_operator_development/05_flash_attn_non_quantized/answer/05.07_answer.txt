05.07 mask 支持 —— 小测验答案

1. mask 生效的拍与方式：
   - 生效在 V1（softmax 之前的 score 加工），紧跟 C1 之后：C1 算出的 S1xS2 score 矩阵，在进 softmax 前把被 mask 的位置改写。
   - 方式：块级整块跳过（不搬不存的省略）+ 边界块的行级/列级改写——用 Vector 指令在 S1xS2 矩阵上批量地把非法位置写成 -inf（softmax 后归零），合法位置不变。

2. sparsemode3 块级跳过省掉的内容与因果掩码能整块跳的原因：
   - 省掉的是整块的「K/V 搬运 + C1 + V1 + C2 + V2」全套成本：如果某 (S1 块, S2 块) 组合完全在掩码外（全部位置都被 mask），这一块的 P 全为 0，对 Output 的贡献是 0，可以整块从 task 列表里剔除——不 DataCopy、不 Mmad、不 softmax。
   - 因果掩码能整块跳：因果 mask 的形状是「下三角」——q 位置 i 只看 k 位置 <= i。若整个 S1 块的最小 q 下标 > 整个 S2 块的最大 k 下标，则块内所有位置全部非法，可整块跳过；反之若整块都在下三角内则整块合法。只有边界块跨在三角斜线上才需要细粒度掩码。这种「连续、单调」的掩码结构正是块级稀疏的前提。

3. 边界落在块中间时的处理与选 Vector 指令的原因：
   - 必须行级掩码：边界块内合法/非法混杂，无法整块跳，需要按行（每个 q 位置的有效 k 长度不同）把行内非法段写成 -inf；不写的话，非法位置的 score 会参与 softmax 分母（l 变大）和 P·V 累加，结果直接错。
   - 用 Vector 而不是 Scalar：掩码是一个 S1xS2（如 128x128）矩阵上的批量改写，Vector 一条指令处理一整行/一段连续元素，配合按行边界生成的 index/长度参数可以一次算完；Scalar 逐元素循环的耗时会被放大 128 倍，把 V1 拍拉长到无法接受。而且行边界（每行的有效长度）本身可以先用少量 Scalar 算好，再喂给 Vector 批量执行——「Scalar 定参数、Vector 干重活」是标准分工。

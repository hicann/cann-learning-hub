《FlashAttention 算子开发课程》第 5 章 5.3 节测验答案
====================================================

1. 等长且 128 对齐意味着没有尾块（S1/S2 都是整齐的基本块）、
   没有 actualSeqLengths 的变长处理——省掉了尾块的搬运/掩码/
   流水收尾等全部复杂度，让第一版代码专注四拍循环本身的正确性。

2. C1（Q·Kᵀ）和 C2（P·V）跑在 Cube（mmad）；
   V1（softmax/mask/scale）和 V2（update/归一化）跑在 Vector。
   P 送 mm2 前要从 FP32 转回 FP16（mm2 输入是 half）。

3. 严格串行交替空等：缓冲先被填（搬运）再被算（计算），
   搬运单元与计算单元轮流空等，总时长 = 搬运 + 计算之和。

《FlashAttention 算子开发课程》第 5 章 5.4 节测验答案
====================================================

1. SPMD 多核并行的前提是核间数据独立；有依赖就必须核间同步，
   一次同步（等待 + 通信）的代价可能吃掉并行收益，
   且同步点会让流水线整体停摆。

2. totalSize = B×N = 1×8 = 8 → blockDim = 8，
   40 个核中 32 个空转——这正是 BN1 任务粒度太粗的问题，
   也是后续引入 S1 切分（BN1S1）与 FlashDecode 的动机。

3. FlashDecode 打破「S2 不做核间切分」的原则：
   Q 和 BS 无法并行时（Decode 每步只有 1 个 token），
   把 K/V 沿 S2 切给多核并行，每核算部分 softmax 状态
   （m/l 局部值、部分加权和），代价是一次跨核归并
   （状态合并 + 部分和重标定相加）的通信开销。

《FlashAttention 算子开发课程》第 5 章 5.5 节测验答案
====================================================

1. Q 在整个 S2 循环中被每一拍反复使用（驻留片上），
   循环前搬一次即可；乒乓的意义是让「逐块流进」的数据
   （K、V）的搬运与计算重叠，Q 没有逐块流进的问题，
   双份只会浪费一倍片上内存。

2. 搬运单元（MTE2）：FreeTensor 释放意味着消费者已用完，
   生产者的 EnQue/SetFlag 可以把下一块数据写进这份缓冲。

3. 变成 max(搬运时间, 计算时间)（长的一方决定）。
   新的浪费在计算内部：四拍之间 C1→V1→C2→V2 有数据依赖，
   Cube 与 Vector 互相等待——这是 5.6 节 preload 要解决的。

《FlashAttention 算子开发课程》第 5 章 5.6 节测验答案
====================================================

1. 依赖链：V1 依赖 C1，C2 依赖 V1，V2 依赖 C2。
   Preload 流水实现 Cube 无断流：把当前轮 V1 对应的 C2
   放到下一轮发射（互换 C1/C2 位置），一轮中用两个
   Cube 阶段（C1、C2）掩盖一个较长的 V1，绕开 V1→C2
   的依赖影响。

2. V1 > C1 ≈ C2 >> V2 说明 Vector 的 softmax 拍最长，
   整体是 Cube Bound（Cube 是瓶颈资源，应尽量不让它空）。
   V1 长会拖住 C2 的发射，造成 Cube 流水断流。

3. 原因（至少两条）：
   ① buffer 数量直接影响基本块大小——份数越多每份越小；
   ② 基本块越小，共享数据的重复搬运越多（Q/V 被反复搬入）；
   ③ 过小的基本块搬运带宽打不满，场景变成搬运 Bound。

4. C2(task - PRELOAD_NUM) 滞后 PRELOAD_NUM 轮发射，
   让 V1 有足够时间完成、C2 发射时数据必然就绪，
   从而把 C2 从「紧贴当前轮 V1 之后」挪到与后续轮 V1
   并行的位置。收尾循环必须有：流水灌满后，
   最后 PRELOAD_NUM 个任务的 C2/V2 还没有发射，
   必须逐个清空，否则结果不完整。

《FlashAttention 算子开发课程》第 5 章 5.7 节测验答案
====================================================

1. 在 V1 拍内生效：把不允许关注的位置的分数加上 -inf
   （布尔 mask 矩阵与 S 逐元素叠加），softmax 后权重为 0。

2. 块级跳过省掉的是「整块的搬运 + 计算 + 流水占用」：
   因果掩码下（第 2 章 2.5 节），S1 块 i 对 S2 块 j
   的依赖是块级单调的——j 超过某边界后整块都在「未来」，
   可以整块不算不搬，计算量近似减半。

3. 块级跳过只能跳整块；当边界（preTokens 或尾块边界）
   落在块中间时，块内一部分行有效、一部分无效，
   必须行级/元素级掩码。用 Vector 指令（Compare+Select）
   是因为 Scalar 单元逐元素处理太慢（一条 VF 指令
   顶 64 个 FP32），掩码数据量大时 Scalar 是瓶颈。

《FlashAttention 算子开发课程》第 5 章 5.8 节测验答案
====================================================

1. BSND 的 padding 是「必须算的浪费」（补齐区占内存、
   甚至参与无效计算）；TND 的尾块是「不算的变长」
   （无 padding 内存浪费，但块大小不齐带来计算与
   流水上的额外处理）。

2. 不处理的话，未初始化列参与 softmax 的 max/exp/sum，
   引入未定义数值（NaN/垃圾值），污染整行结果；
   处理成 -inf 后 exp(-inf)=0，不参与归一化分母，
   数值上等价于「这些位置不存在」。

3. 尾块基本块小、单块 V1 短：掩盖窗口窄，且收尾清空段
   （清空滞后的 C2/V2）占比上升——正常块能被
   2 个 Cube 阶段盖住 1 个长 V1，尾块的短 V1
   盖不满、Cube 相对空闲的比例升高。

《FlashAttention 算子开发课程》第 5 章 5.9 节测验答案
====================================================

1. 多切了 Q 的 S1 轴。totalSize 从 B×N 变为
   B × N × ceil(QS / s1Block)，多了 S1 外层块数一项。

2. 向上取整：每核至多领 ceil(total/aiv) 块，
   最差的核多干不超过 1 块的量——「最差的基本块性能最优」；
   向下取整时会有核多领一整块甚至任务被丢弃/堆积，
   最差核的负载不可控。

3. 任务数不均（任务数≠核数）靠 S1 细粒度切分 +
   splitFactorSize 均摊；任务量不均（batch 变长、GQA、
   尾块叠加）靠带 section 的按计算量分组、GS1 合轴/
   不合轴、乃至切 S2 + 归并（第 9 章内容）。

《FlashAttention 算子开发课程》第 5 章 5.10 节章节测验答案
============================================================

1. 七阶段：
   一 基础极简 FA：单核串行跑对四拍循环（消灭：无，建基线）；
   二 BN1 简单分核：B×N 任务分核（消灭：其他核围观的浪费）；
   三 buffer 复用：Q 常驻 + KV 乒乓（消灭：搬运与计算互相等待）；
   四 preload 流水：C2 滞后发射、互换 C1/C2（消灭：Cube 断流）；
   五 mask：sparsemode3 块级跳过（补全功能 + 省掉未来块计算）；
   六 尾块：QS/KVS 非 128 倍数支持（消灭：对齐假设的限制）；
   七 负载均衡：BN1S1 细粒度分核（消灭：任务数不足/不均的闲置）。

2. S2 不能核间切：Softmax 沿 S2 归一化，一个 Q 块必须见到
   全部 KV 才能算对分母 l，切 S2 引入核间依赖。
   FlashDecode 敢切 S2：因为 Decode 时 Q/BS 已无并行空间
   （每步 1 个 token），切 S2 的收益大到值得付出
   跨核归并（局部 m/l 合并、部分和重标定相加）的通信代价。

3. 串行：单块 = C1+V1+C2+V2 = 3+8+3+1 = 15，
   4 块共 60（首块前搬运另计）。
   Preload 一轮：Cube 侧每轮发射 C1+C2 = 6，
   Vector 侧每轮 V1+V2 = 9（稳态）。
   4 个块：Vector 忙 4×9 = 36；
   Cube 忙 4×6 = 24 < 36 → Cube 在断流
   （被 V1 拖住）；总时长由 Vector 决定 ≈ 36 + 预热/收尾。
   Vector 是瓶颈（V1 长），符合 V1>C1≈C2 场景
   「Cube Bound 资源被 V1 拖出断流」的画像。

4. Q 循环外一次搬入、整循环驻留，没有逐块流进的搬运，
   无需乒乓；BUFFER_NUM=2 依赖第 1 章的 TQue 队列同步
   （EnQue 隐含生产者 SetFlag、DeQue 隐含消费者 WaitFlag）。

5. QS=100、KVS=200、块 128：
   S1 块数 = ceil(100/128) = 1，S1 尾块行数 = 100；
   S2 块数 = ceil(200/128) = 2，S2 尾块行数 = 200-128 = 72；
   唯一的 (S1 块, S2 块) 组合是 (0,0) 与 (0,1)——
   因果掩码下 S1 行 0..99 的有效列边界在 0..99 内，
   S2 块 1（列 128..199）全部在行边界之上（未来），
   可整块跳过；(0,0) 内还需行级掩码
   （行 r 只允许列 ≤ r）。

6. BN1：totalSize = B×N = 2×16 = 32 > 20 核 →
   blockDim = 20，无核闲置，每核领 ceil(32/20) = 2 块
   （前 12 核 2 块、后 8 核 1 块，尾差 1）。
   BN1S1：totalSize = 2×16×ceil(256/128) = 2×16×2 = 64；
   splitFactorSize = ceil(64/20) = 4；核 0..15 各领 4 块
   （4×16=64 恰好分完，64 = 20×3 + 4，前 4 核领 4 块、
   后 16 核领 3 块：4×4+16×3 = 64），
   即前 4 核 4 个任务、其余 16 核 3 个任务，尾差 1 块。

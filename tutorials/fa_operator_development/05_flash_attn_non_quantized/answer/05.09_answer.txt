05.09 BN1S1 负载均衡 —— 小测验答案

1. BN1S1 相比 BN1 多切的轴与 totalSize 的变化：
   - BN1 只切 B 和 N：totalSize = B * N。BN1S1 再切 S1（Q 的 seq 维）：totalSize = B * N * ceil(S1 / splitFactorSize)。
   - 多出来的一项就是 S1 方向的分片数 splitKV/分 Q 的块数：公式多了 (S1 / splitFactorSize)（向上取整）这一因子。
   - S1 可切是因为 Q 分片之间独立（各自算各自的输出行，softmax 是行级操作，行与行不交互）——这也是「Q 可切、S2 默认不可切」的原因（S2 是 softmax 分母，切了要归并）。

2. splitFactorSize 向上取整 vs 向下取整对最差核的影响：
   - 向上取整：每个核分到的 splitFactorSize 偏小，最后一个核的任务量 <= splitFactorSize，最差核的耗时被压到最低——任务数不浪费，但分片更多、每个 task 更小，per-task overhead（buffer 周转、流水填充）占比增大。
   - 向下取整：每个核分到更大的块，per-task overhead 更低，但最后一个核承担全部余数（S1 mod 核数都可能堆在一个核上），最差核的任务量可能显著高于平均，整机等待这个长尾核。
   - 本质是「长尾敏感」与「碎片敏感」的权衡：核数少、S1 大时向上取整更稳；追求极致 per-task 效率时向下取整，但必须配合更细的分配策略（如循环分配而不是连续分配）摊平长尾。

3. 任务数不均与任务量不均的解法：
   - 任务数不均（有的核 5 个 task、有的核 3 个）：靠 splitFactorSize 的取整策略 + 更细粒度的切分（把 S1 切得更碎，让 totalSize 远大于核数，余数影响被摊薄）解决。
   - 任务量不均（task 数一样但每个 task 的实际工作量不同，如尾块核、mask 块分布不均、S2 长度不一）：靠「按代价加权分配」解决——Tiling 阶段对每个 task 估算代价（块数、有效宽度），用贪心/轮转把重 task 与轻 task 搭配着分给同一个核，让每个核的「总代价」而不是「总 task 数」尽量相等。
   - 两个不均往往同时存在：先解决任务数（切分粒度），再解决任务量（代价加权），最后用 mte profiler 之类的工具实测核耗时直方图来验证。

05.03 基础极简 FA —— 小测验答案

1. 「QS 与 KVS 等长且为 128 的倍数」的原因：
   - 等长（QS == KVS）：保证每一轮四拍循环处理的 KV 块都是完整的整块，Q 分块与 KV 分块同步推进，循环边界只需要一个变量控制。
   - 128 的倍数：Cube 矩阵乘的天然原子尺寸是 16x16（Mmad 基本块），128 对齐能让整块完整落在 M/N/K 三个维度上，不需要处理残块。
   - 这个约束帮我们省掉了：尾块处理（边界判断、mask 补 -inf/0、非整块 Mmad 拼接）的全部代码。阶段一可以心无旁骛地先把「四拍循环 + 双侧搬入/搬出」的主干跑通。

2. 四拍循环的分工：
   - 跑在 Cube 的两拍：C1（mm1：S1 x S2 = Q·K^T 得 score 矩阵）和 C2（mm2：S1 x D2 = P·V 得当前块的输出）。
   - 跑在 Vector 的两拍：V1（softmax 行归一化：行 max、减 max、指数、累加）和 V2（update：把当前块输出 rescale 后累加进最终 Output，含 m/l 状态更新）。
   - P 矩阵送 mm2 前要做的转换：数据类型转换——V1 算出的 P 是 FP32（softmax 中间过程必须高精度），而 mm2 的输入要求 FP16/BF16，需要先做 Cast 降精度，同时保持 BSH/BSND 的排布要求（mm2 的 A 矩阵按行主序、B 矩阵按列主序摆放）。

3. 单核串行版本里「搬运」和「计算」的时间关系：
   - 完全串行：MTE2 搬完 → Cube 算 → Vector 算 → MTE3 搬出，任何时刻只有一条流水线在干活，其余全部空等。
   - 总耗时 ≈ 搬运时间 + 计算时间 的简单累加，没有任何重叠。这就是后续所有优化（乒乓、preload）要消灭的「串行浪费」基线。

# 7.1 练习解析

## 1. 产物与阶段的对应关系

| 产物 | 主要形成于哪个阶段 | 后续怎样使用 |
|---|---|---|
| design.md | 设计 | 生成据此实现，ST 和调优核对需要保持的计算与接口约定 |
| 算子代码 | 生成 | ST 实际调用，调优基于它形成候选，代码 Review 检查最终版本 |
| 补充 pytest | ST | 修复和调优后继续运行，并作为后续回归测试保留 |
| 逐案例性能表 | 调优 | 用来判断性能目标是否达成，并支撑最终交付结论 |
| 代码格式检查报告 | 代码 Review | 证明最终代码已经通过约定的格式、lint 与 CI 规范检查 |

design.md、算子代码和 pytest 都会被多个阶段使用。不能把“形成产物的阶段”和“使用产物的阶段”视为一一对应。

## 2. 更快但数值失败的候选

不能交付。数值测试是优化候选必须通过的正确性门禁，速度更快不能抵消结果错误。通常应回到调优阶段放弃或修复该候选；如果失败暴露的是原有实现或设计问题，则继续返回生成或设计阶段处理。修改后还要重新取得正确性和性能证据。

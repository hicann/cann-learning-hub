# 课程调优报告：以 kernel duration 为主目标

## 验收口径

本节关心用户等待的一次完整 kernel 调用，因此以设备侧 `Task Duration` 作为性能验收指标。

性能目标保持任务输入中的约定：全部九项候选/B0 比值不超过 1.05，九项几何均值不超过 0.95，最终完整 ST 必须通过。

## 候选怎样产生

[源码成本分析](semantic_cost_model.md)记录了长行分段归约和指数中间值 UB 读写等事实，候选据此尝试改变归约组织、寄存器状态和中间值生命周期。

课程选取两个判断节点：

- C1 减少分段归约次数，修复正确性问题后整次 kernel 耗时仍明显增加，因此回退。
- C4 在写回时重算指数，换取更少的 UB 中间值读写；正确性通过后进入完整性能复验。

这些节点用于说明候选的筛选方法。本节不声称 C4 是全部可能实现中的全局最优，只判断它是否满足本次交付门槛。

## kernel duration 复验

[完整比较](comparisons/fixed12_Bstar_vs_B0.json)保存了每次测量的 `Task Duration`。课程从其中已有的 `task_duration_us` 与 `task_ratio` 字段形成[课程性能汇总](comparisons/course_kernel_duration_summary.json)，没有重新执行、删除样本或修改原始测量值。

最终 B0、C4 每版每个 case 各保留 12 个样本并取中位数：

- 九项 kernel duration 比值的几何均值为 **0.93321841**，满足 `≤ 0.95`。
- 最差一项是 `(64,128)`，比值为 **1.00791803**，九项均满足 `≤ 1.05`。
- 216 条频率记录处于同一额定频率，没有排除样本。
- 最终完整 ST 为 **90/90**。

因此 C4 达到本次正确性与整体 kernel duration 目标，可以进入最终 Review。

## ledger 与门禁

候选、义务和结果持续写入 [ledger](iteration_ledger.md)。门禁检查候选是否有结果、记录是否闭环以及结论是否前后一致。门禁不能替代业务目标的选择；课程仍需先明确以整体 kernel duration 验收。

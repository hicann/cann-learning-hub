# 练习：让 Agent 完成一次算子交付

本练习使用课程开始时已经拉取的 TileKernels 代码仓，无需另外下载工作流。下文中的 `agent/init.sh` 和 `agent/` 均为相对于该代码仓根目录的路径。

需求和测试案例已经准备好。同学们只需把材料交给 Agent，跟随提示完成设计、生成、ST、调优、Review 和交付。

> 运行中可能出现与课件不同的问题或优化结果，应依据自己的记录作判断。模型、软件版本和设备状态不同，最终过程不一定与课件完全一致。

## 1. 准备材料

下载下面两份必要材料，并放到待开发仓库的同一任务目录中：

- [需求文档](workflow_run/course_inputs/task.md)
- [指定案例](workflow_run/course_inputs/cases.json)

需求已经写好，无需重新整理。

## 2. 初始化工作流

进入课程配套的 TileKernels 代码仓根目录后执行：

```bash
bash agent/init.sh --tool codex --scope project
bash agent/init.sh --tool codex --scope project --check
cd agent
codex
```

前两条命令分别安装并检查项目工作流。安装入口位于仓库的 `agent/` 目录，因此需要进入该目录后再启动 Codex。

## 3. 发送任务

将下面提示词中的 `<任务目录>` 替换为实际路径，复制给 Agent：

> 请读取 `<任务目录>/task.md` 和 `<任务目录>/cases.json`，按当前工作流完成稳定行 Softmax 的设计、生成、ST、性能调优、Review 和交付。进入调优时按工作流暂停选择模式；本练习推荐 Flash 模式。后端使用 AscendC，性能测试使用 `cases.json` 中全部九个 case。实际执行测试和性能采集，保留各阶段产物、失败与回退记录，不删减案例或降低需求标准。工作流要求暂停时，请先给出当前结果和下一步选项。

## 4. 处理暂停节点

工作流在关键节点会等待确认。先看 Agent 的阶段结果，再复制相应回复。

### ST 完成后

工作流会询问是否继续调优，并要求选择调优模式。本练习推荐使用流程较轻量的 Flash 模式；下面是一份可直接复制的推荐回复：

> 继续进行性能调优。本次选择 Flash 模式和 AscendC 后端。性能 case 固定为 `(4,128)`、`(4,2048)`、`(64,128)`、`(64,512)`、`(64,2048)`、`(256,128)`、`(256,512)`、`(256,2048)`、`(68,192)`；均为 float32、连续布局、axis=1、device 0、seed=707，输入为截断到 `[-80,80]` 的标准正态分布。使用全部九项，不筛选代表 case。性能目标按 task.md 执行。

这条回复同时给出了推荐的调优模式、后端和性能 case。

### 调优完成后

> 继续对最终算子和 pytest 进行格式与 lint Review，并给出交付检查结果。

### Review 发现格式问题时

> 同意修复报告中指出的格式问题。修复后重新运行必要检查，并确认测试与性能证据仍对应最终代码。

如果中途出现编译、测试、设备或性能失败，让 Agent 先分析并修正。不要跳过失败，也不要放宽需求标准。

## 5. 查看交付结果

最后让 Agent 列出：

- 最终算子和 pytest 的路径；
- ST 的实际执行结果；
- 九个性能 case 的比较结果；
- 最终 Review 结果；
- 当前是否满足交付要求。

保存这份交付清单和各阶段文件，即完成本次练习。

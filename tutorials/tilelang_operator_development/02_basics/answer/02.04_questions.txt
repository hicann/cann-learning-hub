# 2.4 练习解析

1. 当 `N=2048、num_blocks=4` 时：

   ```text
   tile = 2048 / 4 = 512
   ```

   | bx | begin | end | 处理范围 |
   |---:|---:|---:|---|
   | 0 | 0 | 512 | `[0, 512)` |
   | 1 | 512 | 1024 | `[512, 1024)` |
   | 2 | 1024 | 1536 | `[1024, 1536)` |
   | 3 | 1536 | 2048 | `[1536, 2048)` |

   四个区间首尾相接，没有重叠或遗漏，并且 `tile=512` 是 64 的倍数。

2. 将 `num_blocks` 改为 4 后，kernel 仍使用同一份计算代码，每个逻辑块只处理自己的 512 个元素。完整输出仍应与 `a+b` 精确一致。

3. 当 `num_blocks=64` 时：

   ```text
   tile = 2048 / 64 = 32
   ```

   当前实现每次处理 64 个 float32 元素，又没有尾块处理，因此 `tile=32` 不满足当前支持条件。Host 的 `_validate` 会在编译和设备调用前抛出明确错误。

4. `out_idx=-1` 表示参数列表中的最后一个 Tensor `c` 是输出，调用 kernel 时只需要传入 `a` 和 `b`。`@tilelang.jit` 适合通过工厂参数取得对应的可调用 kernel；`tilelang.compile` 显式接收 `T.prim_func`，本节用它取得并检查生成源码。两种入口都必须通过完整输出比较，不能用源码片段或成功提示代替正确性验证。

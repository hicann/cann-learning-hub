4. 答案：`MEMORY.md`；`.orchestrator_state.json`

判断依据：

- `MEMORY.md` 是双份共享状态之一，定位为人类可读的叙事记录，包含设计思路、决策依据、检查凭证与调试过程，由各智能体从 Stage 5 起读写。
- `.orchestrator_state.json` 是双份共享状态之二，定位为机器可读的状态机文件，记录当前阶段、重试次数、模块状态、产物哈希与回滚记录，供流程从断点恢复使用。
- `SPEC.md` 是 Stage 1 的产物文档、`DESIGN.md` 是 Stage 3 的产物文档，属于各阶段的过程记录，但不是持续更新的双份共享状态。

5. 答案：Verifier；Debugger；Coder；Verifier

判断依据：

- 第一空 Verifier：Verifier 是校验判定方（judge-only），只负责判定 PASS/FAIL 并归类故障（`failure_category`），不编写、不修改 Kernel 代码。
- 第二空 Debugger：Debugger 是调查方（investigator），只负责针对失败文件与故障类型定位根因、给出补丁方案。
- 第三空 Coder：Coder 是唯一编写生产 Kernel 代码的智能体，负责应用 Debugger 给出的补丁。
- 第四空 Verifier：补丁应用后仍由 Verifier 重新校验，当前模块未通过就不会进入下一模块的开发——「编写者不得自行宣布通过」是职责分离的底线。
